# 阿飞·赛博聊球 — 内容生产工作流

## 一、启动

用户提供：**赛事名称 + 中国竞彩网官方数据**

示例：周二007 欧冠 05-06 03:00 阿森纳VS马竞

---

## 二、文章生成流程

### Step 1：数据核查（核心步骤 — 反复犯过错，必须重视）

此步骤分两层核查，缺一不可。

**第1层：联网搜索核实基础事实**
- 用WebSearch确认：比赛性质、时间、场地
- 用WebSearch核实：**关键球员是否还在该队**（姆巴佩2024已去皇马，2026年不可能在PSG；克罗斯已退役或离队）
- 用WebSearch交叉验证：首回合比分、进球者、关键数据
- 用WebSearch核实：历史纪录类表述（"最快进球""最多连胜"必须有出处）
- ⚠️ **用户提供的文本数据可能有误**，自己的训练知识也可能过时。必须用联网搜索做二次确认

**第2层：对照竞彩网截图逐条核对**

拿到用户竞彩网截图后，逐一比对：

| 核查项 | 最容易踩的坑 |
|--------|-------------|
| 积分榜排名/积分 | 新赛制（点球胜2分/点球负1分）与常规积分算法不同 |
| 联赛总战绩 | 场次/胜/平/负必须和积分榜完全一致 |
| **主客场分开战绩** | ⚠️ 客场战绩最容易被忽略，之前犯过错（神户客场写成2胜2平2负，实际3胜0平3负） |
| 近期赛果 | 注意区分联赛/杯赛/亚冠，近况描述要准确 |
| 历史交锋 | 最近5次交锋比分和趋势，注意主客场 |
| 射手数据 | 进球/助攻数字 |
| 伤停信息 | 伤停名单是否影响核心阵容 |

**核查红线（来自历史教训）：**
- ❌ 淘汰赛对手 ≠ 联赛阶段对手（最易混淆）
- ⚠️ **赛制规则必须核查（2026-08-05 新增）** — ① 客场进球规则是否取消（欧足联2021-22取消；巴西杯2020取消；南美解放者杯/南美杯2022取消）② 淘汰赛只有"总比分"，没有"带走3分"概念 ③ 两回合平局 → 加时/点球，推演前先确认晋级规则
- ⚠️ **换帅/新帅首秀核查（2026-08-07 新增）** — 写前瞻前查两队是否换帅、新帅是否首秀（磨合期是重要基本面，例：横滨水手科里卡6/21上任首秀）；竞彩"伤停:暂无数据"≠无伤停，需第三方交叉验证（搜狐/新球/懂球帝）
- ⚠️ **中立场地核查** — 杯赛决赛/揭幕战可能安排在中立场（如东京国立竞技场），"主场优势"论据写前先确认不是中立场地
- ❌ 不能编造球员纪录（"最快""最多"类必须有来源）
- ❌ 不能写未经数据提供的联赛表格的数字
- ❌ **不能照单全收用户提供的文本数据** — 必须用联网搜索 + 截图交叉验证
- ❌ **封面/摘要里的数据必须精确** — "主场5战全胜"有歧义就不行，要写"主场5胜2负"
- ⚠️ **所有数字写进文章前，再读一遍原文对照** — 写稿过程中可能抄错行或看串列

### Step 2：写稿（倒金字塔结构 — 2026-08-05 更新）

**核心原则：最值钱的干货放最前面。碎片化阅读时代，读者没有耐心滑到最后，结论必须第一屏出现。**

结构：

1. **核心偏差（第一屏）** — 直接抛模型 vs 市场的关键偏差："主胜概率57.6%，市场隐含才46.5%——差了11个百分点"。紧接着解释"市场为什么错"（印象分 vs 样本），配模型vs市场Edge图
2. **基本面** — 主客队排名/状态/伤停/主客场差异，穿插对比图表（胜平负构成、进失球对比），不拆分太碎
3. **泊松数据** — 期望进球/概率分布/比分概率表，用"后台模型算了一遍"等自然表述引出
4. **胜负点 + 冷门路径** — 结合数据聊看点（2~4个胜负点 + 2~3条冷门路径带概率），不预测
5. **结尾** — 轮换钩子（见 Step 4 钩子库）+ 口头禅 + 数据来源 + 免责声明

### Step 3：降AI率（朱雀检测，目标50%+人工特征）

**禁用句式：**
- ❌ "先聊点背景" / "先说说XX" / "再来说说XX"
- ❌ "不过赛前有点麻烦" / "但值得注意的是"
- ❌ "所以这场两边都有XX"（"所以"总结句式）
- ❌ "突然想到XX" （"突然想到"是AI标志）
- ❌ "几个我觉得值得关注的点"（列举框架）
- ❌ 每段"主题句+展开论证"的工整结构
- ❌ "不过""然而""此外"等过渡词堆砌
- ❌ 完整平衡的长句（看起来太"完美"）

**做：**
- ✅ 短句分段，每段1-3句
- ✅ 口语词点缀（"凑合""邪门""说实在的""不好说"）
- ✅ 汉字代替数字（"一比二"非"1-2"）
- ✅ 去堆砌式数据清单
- ✅ 引用自然融入，不加开场白
- ✅ **定点改，不要全局重写** — 只修改朱雀标记的段落，避免把已通过的部分改坏
- ✅ 文章标题30字以内

**复盘文章特别注意（2026-05-07经验）：**
- ❌ "赛前分析说"多次重复 — 单篇文章会多次提到赛前分析，每次要用不同表述（"之前写前瞻那篇" / "赛前前瞻写过" / "前瞻说" / "前瞻也写了"）
- ❌ "数据上说""跑过数据的都知道" — 改成"数据方面"或用自然句式引出
- ❌ 复盘用Bold小标题（"第3分钟：一锤定音"）+ "——"分割线 — 改成连续叙事流，不用分段标题
- ✅ 部分数据密集型文章难以达到50%+（如沙职表格数据多），30%左右可接受

### Step 4：头条号排版

**标题 SEO 规范（30字以内，2026-08-06 升级为爆款三式）：**
- 必须含实体词：赛事名（巴西杯/欧罗巴/欧冠）+ 两队队名（搜索直接命中）
- 含痛点词：前瞻/预测/模型/数据/预警
- **禁止俗语**（无信息增量，实测拖垮展现）：主场龙/客场虫/强强对话/谁能笑到最后/激情碰撞/巅峰对决/狭路相逢
  - 反面案例：巴西杯前瞻：弗鲁米嫩塞VS瓦斯科达伽马，主场龙碰上客场虫（展现1805）
  - 正面标杆：欧冠夜：阿拉木图三战零进球，波兹南4-1还收着踢（展现6.4万）；韩K联预警：三场首选全1-1，市场集体误判？（展现1.8万）
- **爆款公式（三选一）：**
  - A·数据反差型：`<赛事>预警：<极端数据>，市场集体误判？`
  - B·模型偏差型：`<赛事>预警：<核心变数>，模型预警主胜被高估/低估<偏差值>个百分点`
  - C·具象场景型：`<赛事>：<主队极端数据>，<客队极端数据>`
- 工具已内置标题校验（afei_generator.py 运行即查俗语+30字上限，违规警告）
- 发布时编辑器"标签"栏打满：赛事名、两队名、足球前瞻、数据分析

**正文模块化（2026-08-06 新增，"赛博聊球"硬核骨架）：**
- 开篇第一句=数据预警（直接甩偏差数字，3秒留人，拒绝套话）
- 【数据偏差池】机构隐含 vs 模型测算 + 结论（偏差X个百分点/被高估/被低估）
- 【战术胜负手】50字内核心战术冲突
- 【比分演算倾向】进球区间 + 首选比分（模型推演）
- 基本面只写数据画像（近X场进失/场均/排名），不写球队历史流水账
- 伤停要写"战术链条影响"（如：主力中锋缺阵→高空球战术失效），不列名单

**标题下信息卡（固定格式，紧跟标题）：**
```
#标签1 #标签2 #标签3        ← 最多3个，与内容强相关（赛事+两队名）

【对阵】主队(主) vs 客队(客)— 联赛排名 vs 联赛排名
【赛事】赛事名+轮次（首回合比分，关键规则）
【时间】X月X日(周X) XX:XX 北京时间
【场地】球场名(城市)
【天气】XX，X℃~X℃
```

- 短句稀疏分段（手机阅读优化）
- 「——」作为章节分割
- 无Markdown语法，直接可复制粘贴
- 结尾互动钩子（**轮换库，避免每篇重复**）：⚠️ 类型前缀（数据质疑型/比分预测型等）只用于内部选型，**发布正文里不要写出来**
  - 套路一·数据实战型（模型偏差大的场次）："蒙特卡洛跑了两万次模拟，XX概率六成九——概率只是概率。XX今晚能守住九十分钟吗？把你的预测比分打在评论区，赛后咱们拿实战赛果来验模型。"
  - 套路二·战术探讨型（基本面反差大的场次）："数据给出了倾向，但场上执行靠人。XX这套低效的进攻体系，今晚真能防得住XX的反击？欢迎在评论区留下你的战术视点，咱们赛后验真。"
  - 套路三·观点征集型（焦点战）："本期走势已拆解完毕，你的核心看点是哪场？评论区亮出你的判断，看看谁是今天的预判之王。"
  - 套路四·数据质疑型（偏差大的场次）："模型跑出的偏差接近一倍——是市场在挖坑，还是模型太保守？评论区留下你的判断。"
  - 套路五·比分预测型（有明确首选比分的场次）："前瞻首选比分是X-X，今晚能验证吗？留下你的比分，赛后回来验模型。"
  - 套路六·战术变数型（伤停/换人可能左右比赛的场次）："如果下半场XX迟迟打不开局面，替补席上谁会是那个破局点？欢迎来聊聊。"
- 话题标签（2026-08-06 用户要求）：**正文里多穿插话题标签**（#赛事名 #两队名，如 #欧联 #比亚韦 #流浪者），开头信息卡3个+正文关键段落再插2-4个，增加头条话题曝光
- 文末固定模块（**标准模板，信任度+合规**）：
  ```
  【数据来源】基础数据取自竞彩官方及海外主流体育数据库,由阿飞个人足球数据模型独立推演。
  
  【免责声明】本文为个人数据模型推演,属体育赛事分析交流,不构成任何购彩及投注建议,请理性看待,适度娱乐。
  ```

**(封面环节已取消)**

## 三、视频口播稿生成（图文→视频转换）

每篇赛前前瞻写完后，顺手出1条2-3分钟口播稿。"一次选题，两种输出"。

### 操作流程

1. **翻视频文案矩阵.md** — 找到当前文章风格对应的口播叙事线（数据先导式→①抛数字②对比展开③主队④客队⑤变量⑥外媒⑦倾向⑧互动）
2. **提取口播素材** — 从文章中提取最有冲击力的2-3个数据，砍掉推导过程，只留结论
3. **写标题+简介** — 标题30字内，简介400字内讲清看点+预测+互动
4. **写口播稿** — 按叙事线走，一句话一行，2-3分钟量（约350-550字）
5. **口播检查** — 读一遍出声，确保顺口
6. **附录输出** — 标题+简介+口播稿附在文章末尾

### 注意事项

- ❌ 不需要画面提示/AI生图提示词/视觉建议
- ❌ 不需要标注时间码（0-5s, 5-18s这种）
- ✅ 只需要标题+简介+纯口播文案

### 口播检查清单

- [ ] 第一句话是钩子（不是"大家好"或"今天我们来聊"）
- [ ] 每句话不超过20字
- [ ] 外媒预测只留分歧最大的2个（"卫报说X，队报说Y"）
- [ ] 删掉了所有推导过程（"因为A所以B"→只留结论）
- [ ] 读一遍出声，不拗口
- [ ] 结尾有互动提问
- [ ] 全文约350-550字（2-3分钟口播量）

**完整参考**：详见 `视频文案矩阵.md`

## 五、矩阵文章（赛后复盘）

比赛结束后，对比赛前分析与实际赛果，写复盘回顾。

### 风格一：FotMob式（时间线战报+复盘，80%/20%）

**特点：** 按比赛时间线推进，把复盘点嵌在关键事件里，读起来是战报，但穿插"赛前分析说过"。

**结构：**
1. 电头/一句话结果
2. 按时间线讲故事（赖斯封堵→刘易斯-斯凯利→萨卡进球→加布救险→哲凯赖什打飞）
3. 关键球员一段（如格列兹曼告别、萨卡回归）
4. 数据验证（xG对比，复盘赛前分析准不准）
5. 结尾统一格式

**写作注意：**
- 不要分割成"赛前说了什么vs实际发生了什么"两块，而是融进去
- 复盘点自然带出，不打断叙事节奏
- 数据对比用xG等客观指标

### 风格二：ESPN式（多板块深度专题）

**特点：** 新闻电头开头（"伦敦——阿森纳..."），多视角分板块，每个板块一个主题，赢家输家各有独立篇幅，带背景故事和深度分析。

**结构：**
1. **电头开头** — 地点+结果一句话（"伦敦——阿森纳时隔20年..."）
2. **赢家板块** — 主队历史意义、教练去留、关键球员故事
3. **输家板块** — 客队失利原因、教练决策、核心球员告别
4. **球星特写** — 单独一段写一个关键球员（如萨卡、格列兹曼）
5. **战术/数据段** — 防线表现、关键数据
6. **展望** — 下一场/决赛前瞻

**写作注意：**
- 每个板块200-300字，独立成段
- 视角平衡，不偏袒一方
- 带背景深度（历史战绩、合同情况、纪录数据）
- 语言偏正式体育媒体风格

### 风格三：SI式（话题深度调查 — 参考用）

**特点：** 围绕一个话题（转会/争议/球员关系）做多方调查，问题驱动结构，从头到尾是"一个悬念的展开"。

**适用场景：** 场外话题、转会传闻、球员争议、深度人物特写。目前账号做的不多，作为风格储备。

**可借鉴的点：**
- **"先立靶再反转"开头** — "都说XX要走了，但俱乐部根本没考虑卖"
- **问题式小标题** — 用设问做分段标题（Why / Could / How），比普通标题更有钩子
- **开放式结尾** — 不强行总结定论，留个思考给读者
- 这些写法不仅限于转会话题，赛前分析也能用（"为什么这场阿森纳能赢？" 然后分点展开）

### 三种风格怎么选

| 场景 | 推荐风格 |
|------|---------|
| 快速出稿，偏战报 | FotMob式 |
| 重要比赛，想深度分析 | ESPN式 |
| 时间紧张 | FotMob式，30分钟搞定 |
| 周末/大战后专题 | ESPN式，可配图分板块 |
| 场外话题/转会/人物特写（储备） | SI式（参考问题式小标题+开放式结尾） |

## 七、通用工具（afei_generator.py — 2026-08-05 新增）

**位置：** `阿飞说球/02_工具/afei_generator.py`

**功能：** 一份 JSON 配置 → 泊松模型 + 5张对比图 + md + Word（含图），一键生成完整赛事前瞻。

**用法：**
```bash
cd /d/Hermes/football
python "阿飞说球/02_工具/afei_generator.py" --config "阿飞说球/02_工具/match_configs/<主队>vs<客队>.json"
python "阿飞说球/02_工具/afei_generator.py" --config xxx.json --model-only   # 只跑模型打印数字
```

**流程：**
1. 复制 `match_configs/弗鲁米嫩塞vs瓦斯科达伽马.json` 为 `<主队>vs<客队>.json`
2. 填：标题/标签/赛事/时间/场地/天气/欧赔/比分赔率/两队联赛数据/战略修正（mult、form）/文章段落（sections）
3. 模型数字（λ、胜平负、比分概率、区间、晋级）**自动计算并填入表格与正文**，与图表永远一致，不手抄
4. 输出到 `04_赛事文章/<主队>vs<客队>/`（charts/ + md + docx）

**sections 类型：** `para`(段落) / `dash`(——) / `data_para`(数据段，支持{pH}{lam_h}{edgeH_abs}等占位符) / `model_table`(胜平负模型表，自动) / `score_table`(比分概率表，自动) / `chart`(插图) / `hook`

**模型数字：** 终端输出含比分EV、Kelly仓位（内部参考，不进文章——合规）；含"Edge校准"行（172场回测修正，价值判断以此为准）
**市场校准：** 自动读取 `00_引擎/backtest/calibration_state.json`（每周一 09:00 cron"竞彩回测校准周更"自动抓赛果→重算→更新），无 state 时用内置系数。回测结论：竞彩平局/冷门隐含虚高、热门隐含偏低。见 `00_引擎/backtest/BACKTEST_REPORT.md`

**坑：** docx 被 Word 打开时会另存 `_new.docx`，关掉 Word 后重跑即可覆盖。

## 零、选题(2026-08-28 头条30篇实测定论)

**流量分水岭=选赛道(决定展现), 标题只决定CTR。** 选题顺序:

| 优先级 | 赛道 | 预期表现 | 写法要求 |
|---|---|---|---|
| T1 基本盘 | 竞彩早场: 日职/韩职/北欧小联赛 | 展现1-2.5万, CTR 9-12% | 标题带竞彩编号("周六001")+双场打包 |
| T2 焦点战 | 五大联赛焦点/欧冠强强 | 展现4000-7500 | 深度数据拆解(巴萨/皇马CTR 10%+已验证) |
| 放弃 | 冷门杯赛/资格赛/西甲升班马/无焦点多场扫描 | 展现<3000, 阅读<200 | 不写, 选题时就淘汰(奥胡斯篇CTR 8.4%达标仍败给赛道) |

- 赛程源: 竞彩官网赛程页(**拉未来2天按"名气×国内球迷基数"排序**,T1基本盘优先); 用户手贴亦可
- 冷启动期额外渠道: 竞彩 API 拉赛程 → 按联赛热度排序 → 双场/串烧候选入池(详见 skill `wechat-gzh-coldstart`)
- 发文时间: 早场=比赛前晚或比赛日11:30前发, 留6-8h发酵; 深夜场=当天20:00-22:00发
- 发布后: 用户报后台三个数(展现/阅读/CTR), 归档 `04_赛事文章/头条发布数据台账.tsv`

## 二、文章生成流程

### Step 1：数据核查(核心步骤 — 反复犯过错，必须重视)

此步骤分两层核查，缺一不可。

**第1层：联网搜索核实基础事实**
- 用WebSearch确认：比赛性质、时间、场地
- 用WebSearch核实：**关键球员是否还在该队**(姆巴佩2024已去皇马，克罗斯已离队)
- 用WebSearch交叉验证：首回合比分、进球者、关键数据
- ⚠️ 用户提供的文本数据可能有误，必须联网二次确认

**第2层：对照竞彩网数据逐条核对**

| 核查项 | 最容易踩的坑 |
|--------|-------------|
| 积分榜排名/积分 | 新赛制(点球胜2分)与常规算法不同 |
| 联赛总战绩 | 场次/胜/平/负必须和积分榜完全一致 |
| **主客场分开战绩** | 客场战绩最易错(神户客场写成2胜2平2负,实际3胜0平3负) |
| 近期赛果 | 区分联赛/杯赛/亚冠 |
| 历史交锋 | 最近5次比分和趋势，注意主客场 |
| 射手数据 | 进球/助攻数字 |
| 伤停信息 | 是否影响核心阵容 |
| **场均进失球数据的水分** | ⚠️ 热身赛刷分要剔除(斯图加特近10场34球=热身刷业余队,锚定正式比赛2.0; 米兰vs威尼斯升班马样本失真) |
| **官网核实(2026-09 新增)** | 主力阵容/主帅人事/夏窗转会以**官网公告**为准(inter.it / acmonza.com 等可 Playwright 无头抓取,详见 skill `club-official-site-data`); 身价需德转或雷速,官网不显 |
| **关键球员中文译名(2026-08)** | 无可靠中文译名不硬编,用"位置+原名"(如"外援前锋 Yengi") |

**核查红线(历史教训)：**
- ❌ 淘汰赛对手 ≠ 联赛阶段对手
- ⚠️ 赛制规则必查: 客场进球规则是否取消(欧足联2021-22取消)、淘汰赛只有总比分、平局→加时/点球
- ⚠️ 换帅/新帅首秀核查; 竞彩"伤停:暂无数据"≠无伤停
- ⚠️ 中立场地核查(决赛/揭幕战可能中立)
- ❌ 不编造球员纪录、不写未经数据提供的联赛表格数字
- ❌ **所有数字写进文章前再读一遍原文对照**(抄错行/看串列)
- ✅ **轮次与赛季背景核对**: 世界杯年联赛延后开赛(2026日职8月底才第4轮=正常, 不是笔误), 该背景可写进正文增加可信度

### Step 1.5：跑模型定角度(先跑模型，再定正文角度 — 2026-08-16铁律)

1. 建 config → `--model-only` 看数字
2. **模型与预设叙事冲突时以模型为准**(伯恩利vs西汉姆教训: 初稿写"客胜不稳"结果模型客胜59.6%被低估15.5点, 全文返工)
3. 判断价值看 **"Edge校准"行** — ⚠️2026-09-10 口径修正后系数≈1.0(平局×1.03/热门×1.004/冷门×0.97), **Edge校准≈裸 Edge**, 工具不再制造假 Edge; 该行仍是标准口径, 但别以为"有系数加持"就更可信
4. 方向无分歧时找"剧本差"(让球盘/净胜/大球小球的差价), 例: 拜仁场=让-2门槛、水户场=让+1低赔侧7点
5. ⚠️ **例外: 欧战强强/跨联赛档位差场景以市场为准**(2026-09-10 四场深分析三错一中的教训) — 模型吃"主队近期状态"权重过满, 而**跨联赛实力档位差是λ盲区**; 此场景λ先下调一档, 模型方向与市场冲突时**不采信模型**, 人工复核阈值从 Edge>30 降到 **±15**
6. **让球盘先看结构再写方向**(2026-09-10 全样本**469场**实测) — 竞彩让球线偏深, **让球方赢盘仅27-32% / 走水23% / 受让方不败68-77%**(让-1: 27%/23%/50%; 让+1: 32%/23%/45%); 别追"打穿"(赢盘与走水赔付不同, 不可合成单一投注项)
   - ⚠️ **2026-09-14 复盘修正: 68-77% 是"全样本基准", 不是单场方向!** 八场复盘里我在 003/007/009/012 四场都把主线写成"热门赢不够", 结果被三场主场热门零封大胜打穿(广岛6:1、弗赖堡5:0、多特3:0, 合计14:1)。
   - ✅ **工具已固化该判读**: `afei_generator.py --model-only` 现输出【让球盘结构】段(config 需带 `hhad` + `handicap_line` 字段):
     · 市场去水后的 让胜/走水/让负 三侧 + 更重的一侧与差距点数
     · **两侧差 <3 点 → 判为"无偏向", 直接输出"不许硬选边"**
     · 与 469 场基准的偏离(只用于判断"比基准强/弱一档", **绝不用来反转方向**)
     · 一行"主线建议"
   - **方向规则(唯一)**: 主线**只跟市场更重的那一侧**; 基准只回答"市场定价是否异常"。写"受让方不败"前先看工具这一行。

**受让盘占位符速查(2026-09-04 实测坑):** `+1受让` 场景**禁用** `hcH/hcA`(会让模型概率倒挂成 2.8%/90.7% 而非 47.6%/29.1%); 改用:
- `pH2` — 重新参数化后的主队胜
- `net_neg1` — 让-1后净胜1球
- `net_neg2` — 让-1后净胜2球

完整占位符列表见 skill `afei-football-content`。

### Step 1.8：Gemini 网页端写稿(2026-09 启用, 防幻觉v1.1)

**写稿路径分流:**
- **本地生成** — `python 02_工具/afei_generator.py --config config.json` 直接出 md/docx
- **Gemini 网页端** — 走 skill `gemini-afei-writer`(v1.1 含防幻觉铁律), 整份提示词在 skill 里复制; 老 txt 文件 `gemini_完整提示词_最终版.txt`(2026-08-22) 已停更, 新规则不再同步回 txt

**Gemini 防幻觉v1.1 铁律(2026-09-07 落地):**
- ❌ **禁止大模型自行搜索球员级数据**(进球数/转会费/伤病状态等); 缺数据 → 标注"待用户提供"或"竞彩暂无数据",**绝不自行脑补**
- ✅ 所有数字必须来自: 竞彩官方数据 / 用户提供 / 已抓取的官网公告
- ✅ 教练姓名/球员对位/转会动态: 无可靠来源**不点名**,改用"位置+原名"或泛指
- ⚠️ 用户提供的文本数据可能有误,落笔前必须与 Step 1 第2层核查对齐

**Gemini 写完回到本地:** 把 md 拉回 → 走 Step 3 降AI(本地+网页终检) → 走 Step 4 头条排版。Gemini 出的稿也要过 `check_release.py`,**不能因为"是人机协作"就放水**。

详细提示词见 `gemini_完整提示词_最终版.txt`,使用流程见 skill `gemini-afei-writer`。

### Step 2：写稿(倒金字塔结构)

**核心原则：最值钱的干货放最前面，结论第一屏出现。**

1. **核心偏差(第一屏)** — 模型 vs 市场关键偏差 + "市场为什么错"，配Edge图
2. **基本面** — 排名/状态/伤停/主客场差异，穿插对比图
3. **泊松数据** — 期望进球/概率分布/比分表
4. **胜负点 + 冷门路径** — 2~4个胜负点 + 2~3条冷门路径带概率，不预测
5. **结尾** — 轮换钩子 + 口头禅 + 数据来源 + 免责声明

**同行爆文拆解落地(2026-08-27)：**
- **【比分演算倾向】答案感写法**: 用 `{top_scores}` 占位符(自动填首选比分Top3), 补切换剧本一句; 命中背书只提已验证场次
- **data_para 双向画像四件套**: 战绩数字→伤停链条→阵型/打法→本场目标
- **串烧小节标题独立带赛事名**(multi_preview.py已内置): 每场成为独立搜索入口

**可选叙事模块(2026-09 扩, 按篇选 1-3 个, 位置错开):**
- 【关键球员对位】(`player_matchup` 占位符) — 主客各 1-2 名核心球员的攻防对位
- 【身价对比】(`value_para` + chart6) — 双方主力身价, 标出"溢价点"和"性价比点"
- 【关键射手对比】(`scorer_table` + chart7) — 联赛射手榜对位
- 【恩怨局】【更衣室热梗】【教练棋局】 — 原有三大叙事模块, 1-3 个位置错开(详见 skill `afei-football-content`)
- ⚠️ 红线: 教练/球员对位素材**无来源不点名**; 身价需德转或雷速, **官网不显**

### Step 3：降AI(双层检测 — 2026-08-28定稿)

**原理(朱雀逆向+humanizer 34模式)：** 核心信号=困惑度(用词可预测度)+突发度(句长节奏)+AI高频搭配词。
**⚠️ 0830实测教训: 模板化结构(【】模块×循环)是头号AI信号, 均匀数字流≠人工信号。** 串烧版比单场叙事版危险一档。

**① 本地预检(每篇必跑, 无限制)：**
```bash
python "阿飞说球/02_工具/zhuque_local_check.py" --file "文章.md"
```
- 启发式评分(句长方差/AI词表/数字流/模块标签/口语锚点), 均值<2.5可发
- **串烧稿严一档: <2.0**(2026-08-30 实测, 模板化最易被判 AI, 串烧稿比单场危险一档)
- 输出嫌疑段落排行, 先改分最高的(定点改, 不全局重写)

**② 网页终检(每日5次, 用在刀刃上)：** matrix.tencent.com/ai-detect 贴文本(≥350字), 结果逐段标红照着改

**写作侧对策(源头不产生AI模式)：**
- 长短句猛切换, 段落长度故意不均
- 避AI词表(值得注意的是/综上所述/彰显/不仅…更是…/值钱/捡便宜), 见 zhuque_local_check.py 源码
- 口语锚点(先抛结论/自己掂量/邪门/磨人)自然穿插
- 具体数据密度拉满但**拆碎插话**, 别整段数字堆砌
- 有立场有情绪: "我不信这个数"/"把握也就五五开"
- 破折号每篇≤6, 长句(>60字)每篇≤1
- 串烧稿出稿后"去四件套化": 【数据偏差池】→"先摆盘口"、【战术胜负手】→"交锋簿单独翻一眼"、【比分演算倾向】→"比分模型排了序"

### Step 4：头条号排版

**标题 SEO(30字以内, 爆款公式):**
- 必须含实体词: 赛事名 + 两队队名(搜索直接命中)
- **2026-08-28 实测定论**: 高CTR=具体数据反差+核心矛盾+门槛悬念("周六001:町田10场只丢5球,水户天皇杯刚输给大学队"); 低CTR=裸百分比自嗨("市场高估14个点")和平铺战绩陈述
- **必带竞彩编号**(周五008/周六001)命中彩民搜索
- 禁止俗语: 主场龙/客场虫/强强对话/谁能笑到最后
- 工具内置标题校验(俗语+30字上限)

**信息卡(紧跟标题):**
```
#标签1 #标签2 #标签3        ← 最多3个, 赛事+两队名

【对阵】主队(主) vs 客队(客)— 联赛排名 vs 联赛排名
【赛事】赛事名+轮次（首回合比分，关键规则）
【时间】X月X日(周X) XX:XX 北京时间
【场地】球场名(城市)
【天气】XX，X℃~X℃
```

**正文模块化：** 开篇数据预警 → 偏差池 → 战术胜负手 → 比分演算 → 基本面 → 伤停战术链(不列名单) → 钩子。正文多穿插话题标签(#赛事 #队名)。

**结尾钩子轮换库(带类型前缀只用于内部管理, 发布不显示)：** 数据实战/战术探讨/观点征集/数据质疑/比分预测/战术变数/冷门探讨, check_release.py 自动查与近3篇不重复

**文末固定模板(生成器自动追加, config 里 ending_hook/ending_line 留空)：**
```
【数据来源】竞彩官方(sporttery.cn)及公开数据库,阿飞模型推演。
【免责声明】本文为个人数据模型推演,属赛事分析交流,不构成购彩及投注建议。
```
- **两条各 ≤40 字(2026-09-12 用户定, 现为 38/37 字)**；改模板时两个断言不能破:
  ① 数据来源须含"竞彩官方" ② 免责声明须**同时**含"购彩"与"投注"(check_release 会断言"投注"存在)
- 模板**单一出处** = `afei_generator.py` 的 `FOOTER_SOURCE`/`FOOTER_DISCLAIMER`; 串烧脚本 `from afei_generator import FOOTER` 复用, 不各写一份(防漂移)

> ⚠️ **改模板必查"按字面量匹配模板"的地方(2026-09-12 实测)**: `check_md_release.py` 原来按模板具体措辞(`'基础数据取自'`)过滤模板行再算长句, 模板一精简过滤器即失效 → 已改为按"以【数据来源】/【免责声明】开头"识别。同类隐患: `multi_preview` 的硬编码行号、`startswith` 插图触发条件。

> ⚠️ **检查脚本的"假阴性"要防(2026-09-12 实测)**: `zhuque_local_check.py` 原来跳过 <60 字的段落, 而按头条规范我们已把段落压到 2-4 行 → **一段都没评分却输出"0.0 分通过"**, 比高分更危险。已修: 段长阈值 60→24 字、单句短段不再一律判 AI(≤45 字不扣分)、并加"评分段落 <3 段则警告分数不具参考性"。**任何"通过/达标"型检查, 都要先确认它真的测到了东西。**

- ⚠️ **改文案必同步 `startswith` 插图触发条件** — 否则图片从 3 张静默掉到 1 张(0903 实测坑)

## 四、视频口播稿生成(图文→视频转换)

每篇赛前前瞻写完后，顺手出1条2-3分钟口播稿。"一次选题，两种输出"。

### 操作流程
1. **翻视频文案矩阵.md** — 找当前文章风格对应的口播叙事线(数据先导式: ①抛数字②对比展开③主队④客队⑤变量⑥外媒⑦倾向⑧互动)
2. **提取口播素材** — 最有冲击力的2-3个数据, 砍掉推导只留结论
3. **写标题+简介** — 标题30字内, 简介400字内
4. **写口播稿** — 一句话一行, 2-3分钟量(约350-550字)
5. **口播检查** — 读一遍出声确认顺口

**注意事项：** 不需要画面提示/AI生图提示词/时间码, 只需要标题+简介+纯口播文案。

**口播检查清单：** 第一句是钩子 / 每句≤20字 / 外媒预测只留分歧最大的2个 / 删掉推导过程 / 读起来不拗口 / 结尾有互动提问 / 350-550字

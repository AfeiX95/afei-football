#### 1B. 外媒与 AI 预测（`scripts/media_intel.py` · 2026-10-20 起）
- 走 **DeepSeek Search / Fetch**（`scripts/ds_search.py`）：Search 与 Fetch 各 5 元/1000 次，失败与无结果不计费，`count` 不影响单价；QPS Search 100 / Fetch 25。
- Key 解析顺序：环境变量 `DEEPSEEK_API_KEY` → `state/api-keys.json` 的 `"deepseek"` → **DSH 自己的 `~/.dsh/.credentials.yaml`**（即「插件管理 → 网页搜索」里配的那把，默认直接复用，不用再存一份）；`DEEPSEEK_BASE` 可指向本地假服务器做联调。
- **实测（2026-10-20 首跑 20261020 九场）**：18 次检索 = 0.09 元，每场稳定拿 5 条源；来源以中文聚合/门户（懂球帝、直播吧、竞彩网、百度体育）＋英文站（Goal / Sports Mole / OneFootball / FotMob / beIN）为主，内容多是**赛前发布会、伤停、历史战绩**，真正写「谁赢」的预测句很少 → 方向线索命中率低，但**家数、权威段位、伤病与新闻发布会口径很好用**。所以卡片 `cv` 的媒体行改成「N 家 · 权威 3 以上 M 家」，不再硬凑「偏谁」。
- 产出 `state/intel/<date>/_media_<date>.json|md`：每场来源表（站点/日期/权威/分数）+ **线索计数**（主/客/平/进球/无信号/疑似否定）+ 逐条命中词 + 比分线索 + 可选正文前 700 字。
- `--apply-cards <cards.json>` 只回填 `cv[0]`（媒体行，写家数与方向分布），技术/综合两行仍手写。
- 🔴 纪律：**情报是内部原料**。公开稿与卡片按 R41 转写——不写比分串、不写百分比、不写「谁赢」；只写「N 家媒体里有几家偏向哪边」这类计数。带否定词的源标「疑似否定」，不当结论。
- ⚠️ 已知局限：`snippet/summary` 是模型摘要不是原文，倾向判定靠关键词，必须人工核原文再落笔。

- **投注页**（SPF/让球/比分/总进球/半全场）→ 市场解析先行版
- **特征分析页**（近况/H2H/积分榜/射手/伤停）→ 深度版前提
- 🔴 **页面去重惯例**：赛果页粘贴后，先 grep `📚知识库/赛后校验/` 查旧批次是否已覆盖同窗口（跨天编号如 周三/周四/周五 可能已并入早批）——只统计真正的新数据，绝不重复计 batch/totals

### 1B. 球队底档：排名 / 身价 / 伤停（`scripts/team_profile.py` · 2026-10-20 起）🔴

模型只吃「近 10 场进失 + 同主客 + 交锋」，吃不到阵容档次。这一层**不参与 λ 计算**，单独列出来做交叉检验：

```bash
python -X utf8 scripts/team_profile.py --date 20261021            # 全部场次
python -X utf8 scripts/team_profile.py --date 20261021 --only 周三007 周三010
python -X utf8 scripts/team_profile.py --discover --max-cid 40    # 重建联赛 cid 表（缓存 state/cache/_dq_cid.json）
```
产出 `state/intel/<date>/_team_<date>.{json,md}`：两队排名、身价、身价比、伤停。

**数据源（实测 2026-10-20）**
- **身价用懂球帝「数据」页整张联赛表**：`https://pc.dongqiudi.com/data?cid=<联赛id>&tab=team&type=market_value&expanded=1`，一行一个队（`皇家马德里 | 15亿` / `柏太阳神 | 1833万`）。整表抓一次就够，**不要逐队抓球队页**——大球队页的「市值」块时有时无。
- 已知 cid：荷甲 1 / 西甲 3 / 英超 4 / 德甲 5 / **欧冠 6 与 510** / 解放者杯 19 / **日职+日乙 509**（59 队，含日乙）；其余 cid 1–40 也是各联赛，解析器按队名查即可。
- **排名**：欧冠用懂球帝联赛阶段 36 队榜（`https://pc.dongqiudi.com/data` 默认页）；日职/日乙/解放者杯**没有榜** → 标缺源，不编。
- **伤停**：竞彩 `state/matches/<id>/injury.json` 对欧冠/日职经常是**空名单（缺源，不是无伤病）**；脚本会退一步从 `_media_<date>.json` 的标题/摘要里按「伤/缺阵/停赛/报销/红牌停」抽句子，标「需核原文」。
- 抓不到的：**Transfermarkt（全 404）**、**雷速（404）**。

**读法**（写进报告「零、球队底档」一节，不写进 λ）
1. 身价比 ≥ 3 倍 = 强队踢弱队，深盘场次别拿近期进失当等价物；
2. 客队身价更高时（如 20261021 拜仁 10.40 亿 vs 阿森纳 13.80 亿），模型的大偏差要打折；
3. 主队身价低但报价偏主队 = 主场定价溢价，属机构一侧常态，不是信号。

### 2. 市场解析（先行版）
- 全表去水：隐含概率 = (1/odds) / Σ(1/odds)；让球三向同法
- 规则标记：C15a/C15b/C35/深盘±2/客热档/**C36 客热分档**/**C37 主让-1**/平局池/C09 溃败区/**双口径失真场（放弃入文）**
- 🔴 **双口径全失真场 = 放弃入文（batch33 补录教训）**：联赛样本<2场 且 近10场热身/杯赛灌水（11:0/7:0级）时，「市场反推兜底」同样不可靠（法兰克福1.63主热→1:4惨败，市场也错）→ **排除出选题，不写进合集**；合集选场不为凑数量纳入无 Edge 失真场
- 🔴 **选场策略（R29 v2，2026-10-07 按 277 篇全量数据重写）**：**王牌**=日职/日乙、韩职/韩K 早场（标题必带竞彩编号 + 让球/让步字样）；**中腰**=瑞超/挪超/芬超、国际赛焦点；**降级**=**五大联赛**、冷门杯赛、深夜场。依据：五大联赛三个分期全部垫底（阅读中位 150/259/310，全期 96 篇占 35% 篇数、中位 192），**日职/日乙是唯一越做越强的品类**（1,076→1,022→2,055）→ 五大联赛降为「有明确结构性机会才做」（观察项 C42）。**双场打包 > 单场**（双场 1,292 > 三场+ 776 > 单场 286）。详见 `📚知识库/写作指南/头条流量分层与选题策略.md` v2.0

**读法（内部研判层，R41：公开稿一个字都不出现）**
1. **必发比例 vs 99 家**：比例明显高于平均 + 模拟盈亏为负 = 成交集中在该结果，机构一侧在该结果上是亏的；冷热指数是这两个数的粗差。
2. **差异分析**：人气比 vs 模型概率的差，差大的一侧说明「钱多但概率不高」，是过热信号不是买入信号。
3. **凯利方差**：差平方越小＝各家越一致；某向显著大于其它两向 = 各家对该结果分歧大，模型的单点读数要打折。
4. **伤停**：这页是**官方名单**（号码/位置/是否缺阵/原因），比分侧为 `float_l`（主）/`float_r`（客）；比 `injury.json` 的空名单可信，优先用它写报告技术面。

# 足球赛事前瞻文章工作流

## 触发条件
用户要求写某场比赛的赛事前瞻/分析文章时触发。

## 第一步：数据采集

### 1.1 竞彩网数据（必须）
- 用户提供 sporttery.cn 的HTML文件或截图
- 提取：胜平负赔率时间序列、让球盘、比分赔率、总进球、半全场
- **铁律：赔率数据只用于内部模型计算，绝不出现在文章正文中**

### 1.2 积分榜（必须核实）
- 来源：fifawatch.com 积分榜HTML 或 用户手动提供
- **铁律：必须联网搜索核实最新积分，不能只靠静态数据**
- 搜索关键词："Group X standings 2026 World Cup" 或 "世界杯X组积分"

### 1.3 出线形势（必须）
- 穷举所有出线/出局场景
- 明确"平局对谁有利""赢球锁定什么"

### 1.4 淘汰赛路径（必须）
- K1打谁、K2打谁、第三名打谁
- 路径差异决定战意强弱

### 1.5 🔥 雷速SWOT数据吸收（2026-07-06新增 — 用户提供时必须）

**当用户提供雷速体育(leisu.com)SWOT页面数据时，必须逐条核查并吸收到文章中。SWOT包含三类核心信息：**

| 数据类型 | 用途 | 优先级 |
|:---------|:-----|:-------|
| **有利情报/不利情报** | 叙事素材——找最极端的1-2条作为"那条暗线"的核弹头 | 🔴最高 |
| **中立情报** | 场地/温度/海拔/裁判/阵容身价——补充数据表缺失项 | 🟡中 |
| **赛外焦点事件** | 独立成段作为"⚡开场风暴"——适合有争议性的赛前事件（红牌风波、政治干预等） | 🔴最高 |

**吸收流程：**
1. 逐条阅读SWOT有利/不利情报，标记最反直觉或最戏剧化的1-2条
2. 核对我已有的文章是否已包含这些信息
3. 未包含的 → 优先补充到：
   - 数据表（新增行或更新现有数据）
   - "那条暗线"独立板块（作为独家叙事角度）
   - "⚡开场风暴"独立章节（如果事件有足够争议性和叙事张力）
4. 已包含的 → 跳过
5. 数据来源标注增加"雷速体育"

**实战案例（2026-07-06 USA vs Belgium）：**
```
SWOT情报 → 吸收:
  • "巴洛贡红牌缓刑一年" → 独立章节"⚡开场风暴" (欧足联抗议+特朗普施压+1970年来首例)
  • "比利时0-2落后→124分钟绝杀逆转" → "那条暗线"段 (更戏剧化的晋级故事)
  • "五道黑色围栏防偷拍" → "那条暗线"段 (绝佳叙事素材)
  • "首发平均年龄29.5岁" → 数据表
```

**⚠️ 每篇SWOT数据都有1-3条未被你初始覆盖的强力叙事素材。跳过了就等于浪费了最能让文章出彩的内容。**
- K1打谁、K2打谁、第三名打谁
- 路径差异决定战意强弱

## 叙事素材池（每篇必选）

写文章前，先打开叙事池选2-3个维度，嵌入对应段落。不单独成章，同维度不连续两篇用同一角度。

```text
加载：read_file("I:\\阿飞说球\\📚知识库\\写作指南\\叙事池.md")
选型：从10个维度中各选1个角度 → 记录到本篇选型记录
轮换：下一篇用不同的角度（查上一篇选型记录）
```

## 第三步：v4.0模型分析

### 3.1 核心四维判断
| 维度 | 问题 |
|------|------|
| 战意差 | 谁更需要赢？已出线/已出局/生死战？ |
| 轮换概率 | 已出线队主力休息概率多高？ |
| 默契概率 | 平局对双方是否都够用？ |
| 实力差 | FIFA排名+近期战绩+xG数据 |

### 2.2 比分推演逻辑
- 最可能比分 = 战意差 × 实力差 × 默契概率 × 轮换折扣
- 已出线队末轮规律：德国1-2、美国2-3、英格兰0-0、日本1-1 → 胜率极低
- 默契球标志：平赔极低（<2.20）、双方平局都够用

### 2.3 输出
- 唯一比分 + 次选比分 + 核心逻辑链

## 第三步：降AI写作（阿飞风格）

### 3.0 比赛类型判定 & 模板选择（v2.0新增 — 必须先选模板再写）

**写文章前，先判定这场比赛的属性，然后从以下3个模板中选择一个。禁止连续两篇用同一模板。**

| 场次类型 | 推荐模板 | 判断依据 |
|:---------|:---------|:---------|
| 强弱分明（模型胜率>60%） | **A-悬疑反转体** | 强队太热→需要制造"冷门可能"的反差 |
| 实力接近（40-50%区间） | **B-硬核对决体** | 胜负难料→拆解关键对位给读者自己判断 |
| 赛后回顾/多场合集 | **C-复盘叙事体** | 以赛果为锚点→模型vs实际→归因 |

---

### 3.0.1 模板A — 悬疑反转体（适合强弱分明场次）

**开头钩子方法：** 直接抛出一个与市场共识相反的结论，制造悬念。

```
"摩洛哥是C组第二不败出线，加拿大1胜1平1负勉强晋级。
表面看摩洛哥稳了。但后台模型跑完14个维度后，发现一个被所有人忽略的变量。
"
```

**骨架结构：**
```
① 开头：反常结论钩子（1-2段）
② 两队数据表 + 模型概率表（数据支撑）
③ 那条暗线：独家变量（更衣室/换帅/天气/裁判）
④ 剧本推演：如果强队赢怎么走，如果冷门怎么走
⑤ 外媒共识 vs 模型分歧
⑥ 复盘总结 + 互动钩子
```

---

### 3.0.2 模板B — 硬核对决体（适合实力接近场次）

**开头钩子方法：** 开局直接亮出三组关键对位，制造"这场胜负藏在细节里"的氛围。

```
"这场1/8决赛的本质就是三组对位：哈兰德vs巴西中卫、巴西边锋vs挪威边后卫、中场控制权。
谁赢下其中两组，谁就晋级。
"
```

**骨架结构：**
```
① 开头：三组对位预览（1段）
② 逐一拆解每组对位（3段，可用小标题）
③ 球队数据表 + 模型概率表
④ 外媒分歧
⑤ 天气/裁判/海拔变量
⑥ 复盘总结 + 互动钩子
```

---

### 3.0.3 模板C — 复盘叙事体（适合赛后/多场合集）

**开头钩子方法：** 以一个反直觉的比赛瞬间或数据切入。

```
"比利时2-2塞内加尔那场，半场塞内加尔1-0领先。
不是比利时踢得差，是他们真的出问题了——更衣室。
"
```

**骨架结构：**
```
① 开头：反直觉瞬间/数据切入
② 多场速览表（场次/赛果/模型vs实际/偏差）
③ 偏差最大的场次深度拆解
④ 对后续比赛的启示
⑤ 互动钩子
```

---

### 3.0.4 模板D — 情绪复盘体（适合偏差复盘场次）

**开头钩子方法：** 以情绪化、个人化的感受切入，先复盘上一场偏差，再带出当前场次。

```text
"兄弟们，昨晚被{上一场}这场伤了。全场踢得跟梦游一样。
{核心球员}的状态碰上{对手}就跟换了个人——不是{对手}有多强，
是那个{关键数据}真的不是偶然。有些队就是天生克你。
说句不好听的，这场有卧底。不是战术层面的，是心理层面的。
整体没心情。简单说两句复盘，然后看今晚的场次。"
```

**骨架结构：**
```html
① 开头：情绪化复盘（1-2段）— 偏差归因 + 对面数据的验证
② 偏差复盘色块/列表（✅/❌/⚠️ 三档标注判断）
③ 当前场次速览表
④ 逐一拆解当前场次（数据表/模型/比分/方向）
⑤ 当前场次比分过关方案
```

**偏差复盘格式（复用）：**
```html
<div class="ab">
<strong>{场次}偏差复盘：</strong>
<ul>
<li>✅ H2H修正后Edge归零的判断正确——模型vs市场,±X.Xpp</li>
<li>❌ 但没想到输得这么难看——全场X-X, 零进球</li>
<li>✅ 克星属性完全验证——连续X届大赛击败</li>
<li>⚠️ 决赛对决：{下轮对阵}</li>
</ul>
</div>
```

**使用规则：** 连续三篇禁止使用同一模板。模板D主要用于用户情绪低落/需要简短快速出文时的替代方案。

### 3.1 标题规范（v2.0修正）

- **标题必须放在文章第一行**，md格式以 `# ` 开头，HTML以 `<h2>` 开头
- 格式：`日期 + 队名VS队名 + 核心矛盾/数据锚点`（≤30字）
- **禁止纯文学化/情绪化标题**（数据已验证CTR偏低）
- **标题公式：**
  ```
  ✅ [日期] + [队名VS队名] + [核心矛盾/数据锚点]
  
  正面案例（高CTR）：
  "7月2日两场1/16速览：模型推演下的AB面" (CTR 8.6%)
  "7月3日西班牙奥地利葡萄牙克罗地亚瑞士阿尔及利亚：三场连轴转"
  
  反面案例（低CTR）：
  "赢了碰C罗输了回家..." (CTR 3.1%)
  "南非的弹弓怎么射穿四倍身价的铁布衫？"
  ```
- 标题下方：`#主队 #客队 #世界杯 · 时间 · 场馆 · 轮次`
- SEO铁律：标题中必须出现双方队名（搜索流量需求）

### 3.1.1 发布时段锁定（v2.0新增）

根据头条号后台实际数据：

| 时段 | 表现 | 适用 |
|:----|:----|:-----|
| **11:00 - 13:30** | ✅ 爆款集中时段 | 午间发，吃午休流量 |
| **20:00 - 21:00** | ✅ 晚间发酵档 | 晚间发，吃饭后流量 |
| 其他时段 | ❌ 展现量明显偏低 | 避免 |

**规则：** 文章必须在11:00-13:00或20:00-21:00发布。其他时段不发布。

### 3.1.2 排版风格轮换（v2.0新增 — 防审美疲劳）

连续发布的文章必须使用不同的视觉风格。参照 `I:\阿飞说球\📚写作指南\风格库.md`：

| 维度 | 可选方案 |
|:----|:---------|
| **色系** | A红黑经典 / B蓝灰冷调 / C绿金轻快 / D暗夜极简 |
| **开头钩子** | ①反差钩子 ②数据锚钩子 ③故事性钩子 |
| **结尾风格** | ①硬立场 ②留白开放式 ③数据复盘式 |

**规则：** 连续两篇不使用相同的色系+开头钩子组合。下一篇发布前先查上一篇用的什么风格。

### 3.1.3 新增模块轮换（v2.5新增 — 每篇至少选2个）

推荐文章结构为：基础数据表 + 核心矛盾 + 模型 + 胜负手 + **至少2个新增模块**。

| 新增模块 | 内容 |
|:---------|:------|
| 🏰 **恩怨故事** | 两队历史交锋的剧情化叙述（关键比赛回顾、球员个人恩怨、复仇动机） |
| 🪪 **更衣室情报** | 伤停更新+核心球员状态+教练赛前言论+内部氛围 |
| 🎬 **比赛剧本推演** | 分时段拆解(0-20'/20-45'/45-60'/60-75'/75-90')+冷门路径 |
| 🌍 **外媒对比** | 3-5家外媒预测+核心观点+Opta超级计算机数据 |
| 💰 **身价对比** | 两队总身价对比+核心球员身价+FIFA排名 |

**轮换规则：** 连续两篇使用不同的新增模块组合。如果上一篇用了"恩怨故事+外媒对比"，下一篇就换"更衣室情报+剧本推演"。

### 3.2 内部分析头部规范（非头条输出）
全维度分析报告头部必须包含：
```markdown
> **比赛定位：** 一句话点透双方本质（如"反击型东道主 vs 防守体系成熟的非洲强队"）
> **球队标签：** 🇨🇦 高节奏反击队（波动型） | 🇲🇦 低失球+高纪律队（稳定型）
```

### 3.3 比赛剧本推演（内部分析强制章节）
每场内部分析必须包含时间窗口推演：
```
上半场（0'-45'）— 抢开局 vs 稳守
  • 0-15'窗口：大概率事件 + 概率
  • 15-30'窗口：趋势变化
  • 30-45'窗口：比赛节奏预测

下半场（45'-90'）— 体能vs控制
  • 45-60'窗口：调整期
  • 60-75'窗口：关键窗口（体能瓶颈→空间扩大）
  • 75-90+：终局阶段

冷门路径：2-3条小概率但可能发生的剧本
剧本概率分配：主胜/平/客胜 + 极端情况
```

### 3.1.5 独家叙事角度（每篇必找）\n\n头条文章竞争的不是数据——10个来源都能跑模型。竞争的是**独家角度**。\n\n每篇文章必须找到一个其他来源没提的独家切入点：\n- **更衣室变量**：换帅/内讧/核心伤退/管理层动荡（最大价值独家角度）\n- **教练恩怨**：旧帅倒戈/师徒对决/被前东家拒绝\n- **数据逆向**：人人都看好→你指出被忽略的漏洞；人人看衰→你找到被低估的理由\n- **球场因素**：极端天气/场地尺寸/海拔（有具体数据支撑）\n\n找到独家角度后，把它放在文章的\"那条暗线\"独立板块，让读者读到那里时有\"哎这个我之前没想到\"的感觉。\n\n### 3.2 正文风格
- 字数：1200字左右
- **降AI五要素**（必须包含3-5处，不均匀分布）：
  1. 脏话/粗口（适度，如"说白了""他妈的"）
  2. 跑题比喻（金庸/三国/武侠/历史类比）
  3. 不完整句（省略主语、断句）
  4. 视角滑动（从上帝视角突然切到球迷视角）
  5. 反问/自问自答

### 3.3 数据呈现
- 用表格（对比表/概率表/出线情景表）—— **必须用标准`<table>`标签**
- 数据必须融进段落，不能单独堆砌
- **核心铁律：数据用"后台模型""核心判断"等表述，绝不出现具体赔率数字**

### 3.3.1 ⚠️ 头条号排版兼容性（2026-07-07实战确认）

**头条号编辑器对CSS布局支持极其有限。以下元素复制过去一定会乱：**

| ❌ 不能用 | ✅ 替代方案 |
|:---------|:-----------|
| `display:flex` 弹性布局（卡片/横条等） | **标准`<table>`表格** |
| `display:grid` 网格布局 | 多个独立表格或用`<hr>`分隔 |
| `div`+CSS实现的圆角卡片/色块 | `<table>`配合`<td>`的`background-color` |
| `span`内联样式百分比 | 直接写文字 |
| `::before`/`::after`伪元素 | 不用伪元素，用文字符号(📊🏆等)代替 |

**实战案例（2026-07-07 法国vs摩洛哥）：**
```
❌ 原版：.score-row { display:flex } 比分卡片 → 粘贴后全部平铺成一列
✅ 修正后：标准<table><tr><th>赛果</th><th>概率</th></tr> → 完美保留格式
```

**规则：每篇HTML文章的表格、概率展示、比分排名全部用标准`<table>`。不要用div+flex实现布局。**

### 3.4 签名语录轮换（v2.3新增 — 防固定语录疲劳）

**禁止连续两篇文章用同一句收尾语录。** 以下语录库轮换使用：

| 语录 | 适用场景 | 使用频率 |
|:-----|:---------|:--------:|
| 难说。真说不好。 | 通用默认 | 40% |
| 足球这东西，谁说得准呢。 | 悬疑/反转场次 | 20% |
| 反正我是信了。 | 自信判断场次 | 20% |
| 走着瞧。 | 争议/焦点战 | 10% |
| 你们觉得呢？ | 用来替换互动钩子的开放收尾 | 10% |

**规则：** 发文前查上一篇用的哪句，本篇换不同的。连续两篇不要重复。

### 3.6 互动钩子强制植入（v2.0新增 — 解决0评论问题）

**当前问题：** 阅读量2000+但评论为0 → 朱雀系统判断"用户不感兴趣" → 后续文章推荐量下降。

**规则：** 每篇文章必须植入**2个互动钩子**，位置固定：

**钩子A — 数据争议提问**（放在模型概率表/比分表之后）：
```
正文示例：
"模型跑出来墨西哥的胜率是35.8%，和市场上英格兰让0.25的数据偏差很大。
你们觉得是高原加成被低估了，还是英格兰确实没那么强？"
```

**钩子B — 个人倾向引导**（放在复盘总结之前）：
```
正文示例：
"说实话，我个人更偏向墨西哥不败的方向。上轮哈兰德那场我也是这么站的，
结果被打脸了。这次你们怎么看？"
```

**互动钩子设计原则：**
1. ✅ 必须与上文数据相关（不能突兀）
2. ✅ 必须预设两个对立立场（让读者想反驳）
3. ❌ 不能用温和提问（"你们觉得呢"太弱）
4. ❌ 不能自问自答（不给标准答案）

### 3.8 ⚡开场风暴独立章节（2026-07-06新增 — 用于有争议性赛前事件的场次）

**当一场比赛有重大的场外争议事件（红牌缓刑、政治干预、纪律处罚反转等）时，将其单独成段放在该场次开头，作为"⚡开场风暴"独立章节，不混入正文叙述。**

适用场景：
| 事件类型 | 案例 | 放置位置 |
|:---------|:-----|:---------|
| 🔴 纪律处罚反转 | 巴洛贡红牌缓刑一年（1970年首例） | ⚡开场风暴（该场次第1段） |
| 🔴 政治介入 | 特朗普/政府层面施压FIFA | ⚡开场风暴（合并到上述段落） |
| 🟡 大规模舆论争议 | 欧足联/媒体炮轰决定 | ⚡开场风暴（放在事件描述之后） |

**写法原则：**
1. 先用1-2句说清楚"发生了什么事"
2. 再用1-2句呈现"为什么这事有争议"
3. 最后用一个反问收尾："这件事是让X队更团结，还是让他们心态失衡？"
4. 长度不超过一个独立章节（3-5段）

该格式替代常规的"那条暗线"开篇——开场风暴负责引爆情绪，那条暗线负责深度拆解。

```markdown
文章写入后，先扫一遍"今天/明天/昨天/刚刚/几个小时前"等时间锚点词：

- "今天这场" → 改为"这场比赛"（今天写≠今天读，发文后读者可能在明天看到）
- "昨天那场" → 改为具体日期或"此前那场"
- "刚刚结束" → 改为事件本身描述

核心原则：文章不写时间锚点，只写事件本身。
发文时间≠读者看到的时间。时间锚点会让文章在24小时后显得过时。
```

## 常见陷阱

1. **积分错误** → 必须联网核实，不能只靠数据库
2. **淘汰赛路径错误** → 必须从赛程HTML逐条提取Match编号
3. **把HTML的FT当已赛结果** → 必须比对当前日期
4. **默契球误判** → 平赔>2.50不算默契，<2.20才算
5. **已出线队=一定翻车** → 葡萄牙有金靴动力≠英格兰式默契
6. **赔率泄露到正文** → 发布前全文搜索"赔率""盘口""@"等关键词
7. **博彩术语漏网** → "稳胆""上车""跟单""打穿""穿盘"等词在正文中容易被忽略，发布前必须全文搜索所有禁用词
8. **数据没放表格** → 对比数据、概率、积分榜等信息必须用表格呈现，不要纯文字堆砌
9. **头条号输出用.md格式** → ❌ 头条不支持Markdown，必须用HTML格式，浏览器打开→全选复制→粘贴
10. **免责声明含"不构成投注建议"** → ❌ 改为"仅供参考"，暗示性更弱、更安全
11. **数据来源含"竞彩网"** → ❌ 改为"懂球帝、ESPN、各队官网"，避免关联博彩平台
12. **多场标题超30字** → 多场六队名+日期共30字极限，用无VS直连格式压缩（如"7月3日西班牙奥地利葡萄牙克罗地亚瑞士阿尔及利亚"）
13. **外部文章忽略未吸收** → 用户提供外部分析时，必须拆解并吸收其框架化元素（比赛定位/关键对位/剧本推演），不能忽略。详见 `match-model-pipeline` 的 `references/external-analysis-absorption.md`
14. **⏰ 时间锚点** → "今天这场""昨天那场""刚刚"等词在文章中出现，读者在24小时后看到会觉得奇怪。发布前全文搜索"今天/明天/昨天/刚刚"，全部改为事件本体描述。
16. **伤病/伤停语言过于绝对** → 用"确认缺阵""确认伤缺"等绝对措辞存在风险（实际阵容可能赛前最后一刻变化）。改为"大概率缺阵""可能上不了"，保留缓冲空间。
17. **"赔率"一词在标题/小标题中出现** → 即使不是直接博彩语境（如"那条暗线：主队魔咒和1.23的赔率"），平台AI仍可能判定违规。全文搜索"赔率"二字，全部替换为"定价""数据""数字"等中性词。
18. **数据采集标注行默认不放** → 用户此前明确要求删除该行。默认不使用，除非用户明确要求添加。
19. **正文数据重复（v2.4新增）** → 同一数据不要同时出现在相邻段落和高亮色块中。正文写了一组关键数据，色块就写另一个角度的信息(如正文说"挪威58%进球来自哈兰德"，色块就写"锁死哈兰德=锁死挪威")，不重复同一组数字。用户对此敏感。
20. **色块与正文信息不重叠（v2.4新增）** → `highlight-box`/`alert-box`/`green-box` 应承担"补充信息"而非"重复信息"的功能。色块放在正文段落后，如果色块内容只是复述了刚写过的数据，删掉色块或改写。
21. **三场同时间开球（如18:30三场同开）** → 在同时间开球的三场合集中，每场标题后时间统一标"18:30"而非逐一不同时间。排版建议：三场全景表放在开头作为导航，每场独立段落中不再重复时间，节省篇幅。

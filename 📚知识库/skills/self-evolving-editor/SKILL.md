# Self-Evolving Editor 自我进化编辑器

> 定位：赛后复盘 → 偏差分析 → 自动修正规则 → 模型迭代
> 核心价值：让模型越用越准，每次赛果都变成下一次的养分
> 搭配使用：model-parameters.json + 修正规则.md + 工作记忆.md

---

## 一、工作流程

```
赛果输入 → 预测vs实际对比 → 偏差分类 → 规则生成 → 参数更新 → 交叉验证
```

### 1.1 赛果输入

每场比赛结束后，收集：
- 实际比分（90分钟）
- 半场比分
- 控球率/射门/射正
- 关键事件（红牌/点球/乌龙）
- 赛后主帅发言摘要

### 1.2 预测vs实际对比

| 对比维度 | 方法 | 输出 |
|:---------|:-----|:-----|
| 胜平负方向 | 模型最高概率 vs 实际结果 | 命中/偏差 |
| 比分预测 | 首选比分 vs 实际比分 | 距离评分 |
| 概率偏差 | 市场隐含概率 - 模型概率 - 实际结果 | 偏差pp |
| 让球结果 | 让球-1方是否赢盘 | 赢盘率 |

### 1.3 偏差分类

| 偏差类型 | 定义 | 修正方向 |
|:---------|:-----|:---------|
| 方向性错误 | 模型预测主胜，实际客胜 | 检查λ值计算+修正规则 |
| 概率低估 | 平局概率20%但实际发生 | 上浮该场景平局基础概率 |
| 概率高估 | 主胜概率60%但未发生 | 下调该场景主胜概率 |
| 让球误判 | 让球-1方输盘 | 加强C09/C12/C15修正 |
| 冷门遗漏 | 模型未识别的冷门信号 | 新增修正规则 |

## 二、自动修正规则生成

### 2.1 触发条件

```
IF 偏差 > 15pp AND 同类型比赛累计偏差 > 30pp
THEN 生成新修正规则候选
```

### 2.2 规则生成模板

```markdown
### C[编号] [规则名称]
- **触发条件**：[具体场景描述]
- **修正量**：[概率调整pp范围]
- **逻辑**：[为什么这个场景需要修正]
- **验证**：[哪些比赛验证了这条规则]
- **置信度**：[高/中/低，取决于验证场次]
- **待验证**：[还需多少场次确认]
```

### 2.3 规则优先级

| 优先级 | 条件 | 处理 |
|:------:|:-----|:-----|
| P0 | 同规则3次验证失败 | 废弃或大幅调整 |
| P1 | 新发现的系统性偏差 | 立即新增规则 |
| P2 | 单场偶发偏差 | 观察，暂不新增 |
| P3 | 规则置信度提升 | 更新置信度等级 |

## 三、模型参数自动更新

### 3.1 更新范围

| 参数 | 更新条件 | 更新方式 |
|:-----|:---------|:---------|
| draw_base_probability | 平局偏差>10pp累计3场 | 调整基础上限 |
| handicap_minus1_reduction | 让球-1输盘率>60% | 加大修正量 |
| overheat_rules | 过热信号命中率>70% | 收紧阈值 |
| 新增corrections | 新规则通过验证 | 添加到JSON |

### 3.2 更新流程

```
1. 计算最近5场的平均偏差
2. 识别系统性偏差方向
3. 生成参数调整建议
4. 写入 model-parameters.json
5. 同步更新 修正规则.md
6. 同步更新 工作记忆.md
7. 交叉验证：用新参数回测历史数据
```

---

## 四、交叉验证机制

### 4.1 回测方法

```
用新参数重新计算最近20场的模型输出
对比新旧参数的准确率差异
IF 新参数准确率 > 旧参数 + 2pp
THEN 采纳新参数
ELSE 保留旧参数
```

### 4.2 防过拟合

- 单次更新最多调整1-2个参数
- 每个参数调整幅度不超过原值的20%
- 新规则至少需要3场验证才能升为「高置信度」
- 定期（每10场）做一次全局回测

- 提升：+2.3pp ✅ 采纳

## 七、注意事项

1. **保守更新**：宁可少改不多改，避免过拟合
2. **证据充分**：单场偏差不足以生成规则，需要累计验证
3. **可追溯**：每次更新必须记录在工作记忆.md中
4. **人工审核**：P0/P1级规则变更建议通知用户确认
5. **版本控制**：每次重大更新递增 model_version

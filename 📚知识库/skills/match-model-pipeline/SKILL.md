# 赛前模型运行管线

## When to Use

- 写任何赛事前瞻/分析文章之前，必须先跑这个模型获取量化数据
- 用户提供竞彩编号或对阵双方时
- 无论强弱对话、杯赛联赛均适用

## Pipeline Steps

### Step 0: 检查本地已有分析（写模型前先干这个）

**在跑新模型之前，必须检查本地是否已有该场次的分析文件：**

1. 搜索 `I:\阿飞说球\📚知识库\比赛分析\` 下有没有该场次的分析md
2. 搜索 `I:\阿飞说球\📅赛事\{日期}\` 下有没有 `*模型分析*` 或 `*赛事前瞻*` 文件
3. 如果已有完整数据（含λ/MC/EV/品牌溢价/裁判信息/伤停细节），**直接用，不重跑**
4. 如果只有部分数据，补缺即可

**实战教训（2026-07-01 西班牙vs奥地利）：** 本地已有完整仪表盘文件，未查→重跑→用错数据→多轮修正。先查本地能省30分钟。

### Step 0.5 🔥 战略目标判断（AFEI引擎L0.5 — 最关键一步，不可跳过）

**在计算任何xG之前，必须先回答这个问题：双方各自的目标是什么？**

```
比赛阶段判断 → 战略目标分析 → xG修正系数

淘汰赛首轮：
  强势方（FIFA排名/身价明显领先）：目标="90分钟解决"
    → 进攻xG×0.90，防守xG×0.85~0.90
  弱势方（明显下狗）：目标="不输（拖入加时）"
    → 进攻xG×0.50~0.60，防守xG×0.85（摆大巴）

实力接近淘汰赛：
  双方目标="全力争胜"
    → 弱势方xG×0.85 / 强势方xG×0.95

小组赛末轮（已出线双方）：
  目标="控分/轮换"
    → 双方xG×0.70~0.80
```

**实战案例（2026-07-03 瑞士vs阿尔及利亚）：**
- 瑞士(Group B 1st, FIFA 16, €3.3亿) vs 阿尔及利亚(Group J 3rd, FIFA 29, €2.6亿)
- 强势方(瑞士): 目标="90分钟解决" → xG×0.90
- 弱势方(阿尔及利亚): 目标="不输(拖入加时)" → xG×0.55
- 场地: 温哥华室内恒温 → 无天气修正

**⚠️ 没有L0.5判断就直接算λ = 跳步。跳步是模型偏差的最大来源。**

### Step 0.6: 核实小组赛数据完整性和时效性

**在输入任何λ计算之前，确保小组赛数据是完整的：**

- Wikipedia小组页顶部的 "Updated to match(es) played on" 日期可能早于当前日-2天
- 在这个日期之后的比赛结果（尤其是MD3末轮）会缺失
- **必须**从懂球帝或竞彩网赛果补充完整的小组赛最终数据

**核心原则：** 不凭FIFA排名或球队名气脑补小组赛战绩。"世界杯第1"≠"三战全胜"。每队小组战绩必须逐场核实再输入模型。

### Step 2A: 实时数据获取（优先）—— 竞彩网API

#### 方法A1: 一键拉取所有场次（推荐，2026-06实战验证）

```bash
curl -s 'https://webapi.sporttery.cn/gateway/uniform/football/getMatchCalculatorV1.qry?channel=c'
```

#### 方法A2: Python脚本——按竞彩编号匹配目标场次

**直接复制以下代码，把 TARGET_MATCH 改成你的目标场次（如 周三080）：**

```bash
python3 -c "
import json, math
from urllib.request import urlopen, Request
TARGET_MATCH = '周三082'
url = 'https://webapi.sporttery.cn/gateway/uniform/football/getMatchCalculatorV1.qry?channel=c'
req = Request(url, headers={'User-Agent': 'Mozilla/5.0'})
data = json.loads(urlopen(req, timeout=10).read())
for day in data.get('value',{}).get('matchInfoList',[]):
    for sub in day.get('subMatchList',[]):
        mid = sub.get('matchNumStr','')
        if TARGET_MATCH in mid:
            ha, aa = sub.get('homeTeamAbbName','?'), sub.get('awayTeamAbbName','?')
            had = sub.get('had',{}); hhad = sub.get('hhad',{})
            print(f'{mid} {ha} vs {aa}')
            print(f'  胜:{had.get(\"h\",\"?\")} 平:{had.get(\"d\",\"?\")} 负:{had.get(\"a\",\"?\")}')
            print(f'  让球-1: 胜:{hhad.get(\"h\",\"?\")} 平:{hhad.get(\"d\",\"?\")} 负:{hhad.get(\"a\",\"?\")}')
            h,d,a = float(had.get('h',1)), float(had.get('d',1)), float(had.get('a',1))
            t = 1/h+1/d+1/a
            print(f'  市场隐含: {ha}{(1/h)/t*100:.1f}% / 平{(1/d)/t*100:.1f}% / {aa}{(1/a)/t*100:.1f}%')
"
```

输出示例：
```
周四083 西班牙 vs 奥地利
  胜:1.23 平:4.75 负:9.40
  让球-1: 胜:1.85 平:3.55 负:3.25
  市场隐含: 西班牙72.0% / 平18.6% / 奥地利9.4%
```

返回JSON结构：`value.matchInfoList[].subMatchList[]`，关键字段：

| 字段 | 含义 |
|------|------|
| `had` / `hhad` / `crs` / `ttg` / `hafu` | 各彩种赔率（对象嵌套） |
| `homeTeamRank` / `awayTeamRank` | 排名 `[世界杯1]` |
| `matchStatus` | `Selling`=在售 |

**⚠️ API限制：仅返回包含当前营业日的场次。** 实测 `getMatchCalculatorV1.qry` 在2026-07-20只返回周一(当日)的3场瑞超/芬超，不返回周二(次日)的韩职场次。**韩职/次日场次的赔率无法从API获取**，须依赖用户提供的竞彩网特征分析页（已有赔率数据）或固定奖金页HTML。

**对策：** 当用户同时提供特征分析页HTML时，优先从页面中提取赔率数据（特征分析页顶部包含最新固定奖金），或根据球队排名/主客场数据估算市场隐含概率。

**⚠️ API返回数据范围说明：** 实测仅返回**当前营业日**（businessDate=今日）的场次，**不保证返回未来营业日**。用 `matchNumStr`（如周三080）或队名匹配目标场次时，如未匹配到可能是营业日不在当前批次。

**注意**：`matchId` != `mid`，须用 `matchNumStr` 匹配

**⚠️ 特征分析页数据（伤停/历史交锋/射手）不在API中，需从用户粘贴的HTML提取。**

#### 方法B: 从赔率反推原始λ（用于双方法校验）

```python
fairH = (1/hOdds) / (1/hOdds + 1/dOdds + 1/aOdds)
fairA = (1/aOdds) / (1/hOdds + 1/dOdds + 1/aOdds)
lambda_home_raw = 0.4 + fairH * 3.2
lambda_away_raw = 0.2 + fairA * 3.2
```

### Step 2B5 🔥 **十二维变量全检**（v2.5 新增第12维：淘汰赛"主客魔咒"）

在进入λ计算之前，必须逐项检查以下11个维度，确保没有遗漏的重大变量。**每场必检，不可跳过。**

| # | 维度 | 检查内容 | 典型影响 |
|:-:|:----|:---------|:--------|
| 1 | ⚽ 关键射手 | 头号射手状态/进球占比/是否伤缺 | 进球集中度>40%→被针对性防守 |
| 2 | 🧤 门将 | 主力门将状态/身价差/大赛经验 | 身价差>10倍=重大变量 |
| 3 | 📈 近期状态 | 近10场W-D-L + 小组赛完整战绩 | 不败纪录/连败修正form指数 |
| 4 | 🎯 战术风格 | 阵型/核心打法/克制关系 | 传控vs大巴=不同λ修正 |
| 5 | 🌡️ 天气/场地 | 温度/湿度/室内外/海拔/赛季状态 | 高温×0.9，暴雨×0.92，室内=none，**休赛队vs赛季中队** |
| 6 | 👨‍⚖️ 裁判 | 主裁姓名/国籍/执法风格 | 场均黄牌数→宽松哨利好弱队 |
| 7 | 🔄 教练恩怨 | 教练是否执掌过对手/旧帅倒戈 | 熟悉对手体系→战术针对性极强 |
| 8 | 🏠 更衣室 | 内乱传闻/帅位不稳/核心球员不满 | 士气修正-5~15% |
| 9 | 💪 体能/行程 | 飞行距离/休息天数/时差 | 长途飞行+短休息=体能折扣 |
| 10 | 📊 身价 | 总身价比/五大联赛球员占比 | 品牌溢价公式输入 |
| **11** | 🔄 **教练稳定性** | **当前执教时长/赛前有无换帅/帅位安全/首次带队大赛?** | **赛前<6月换帅→士气-10~15%；新手教练→临场风险🔴** |
| **12** | 👻 **淘汰赛"主客魔咒"** | **锦标赛中名义主队是否持续输球？赛事是否有主场魔咒规律？** | **2026世界杯1/8决赛已赛6场，名义主队4/4全灭→魔咒效应🔴** |

**数据来源：**
- 裁判：搜索 `"TeamA vs TeamB 2026 World Cup referee"` 或 `"FIFA World Cup 2026 appointments round of 32"`
- 教练恩怨/更衣室：搜索 `"{coach name} former team"` + `"{team} locker room"` + `"{team} coach sacked rumors"`

### Step 2C: 竞彩网特征分析页数据提取（⚠️ 必须，不可跳过 — 官方数据优先原则）

**核心铁律：竞彩网官方数据 > 搜索引擎数据 > 赔率反推。**

2026-07-06 赫根vs佐加顿斯案例：web_search查到赫根"10场5胜5平0负"的赛季总数据被误读为H2H数据，得出"赫根H2H占优"的错误结论。竞彩网特征分析页明确显示H2H为"赫根3胜2平5负"——方向完全反转，从赫根43%→佐加顿斯41%(Edge+6.9pp)。

**数据源优先级强制执行：**
1. **竞彩网特征分析页**（历史交锋/积分榜/近况/射手/伤停）→ 最权威
2. **竞彩网固定奖金页**（赔率时间序列/TTG）→ 第二
3. **竞彩网API**（JSON）→ 第三
4. **web_search**（ESPN/SoccerPunter/FBref）→ 仅当竞彩不可用 ⚠️
5. **赔率反推** → 仅补充校验

**⚠️ H2H数据读取陷阱（2026-07-06）：**
务必区分「赛季总战绩」和「两队间H2H战绩」：
```
❌ 误读：SoccerPunter"赫根10场5胜5平0负"→以为是H2H数据
✅ 正确：竞彩网特征分析页"历史交锋"→"近10场赫根3胜2平5负"
```
**判断规则：** 如果H2H数据与赔率明显矛盾（如排名低但赔率低），大概率读错了数据源。

当用户提供竞彩网HTML数据时，**必须同时提取两个页面**：

1. **固定奖金页** — 赔率时间序列（用于市场隐含概率）
2. **特征分析页** — 以下关键数据：

| 数据模块 | 对模型的影响 | 修正幅度 |
|---------|-------------|---------|
| 伤停一览 | 核心球员OUT → lambda直接下调 | -5~15% lambda |
| 历史交锋 | 近期结果反映心理状态 | 定性参考 |
| 比赛近况(10场) | 不败纪录/低迷状态修正 | 修正form指数 |
| 射手信息 | 进球集中度 → 被针对性防守风险 | -0~5% lambda |
| 积分榜 | 小组排名（淘汰赛阶段仅为历史数据） | 定性参考 |

**实战教训（2026-06-29/30 三场验证）：**

| 场次 | 仅用赔率法 | 加入伤停后 | 偏差 | 核心变量 |
|:----|:---------:|:---------:|:----:|:---------|
| 巴西vs日本 | 巴西75.6% | 巴西52-62% | 23pp | 拉菲尼亚(右边锋)OUT |
| 德国vs巴拉圭 | 德国75%+ | 德国72%(实际1-1❌) | 3pp+ | 穆西亚拉(中场核心)OUT |
| **墨西哥vs厄瓜多尔** | 墨西哥45% | **墨西哥61%** | **15pp** | **凯塞多(中场核心3/3)OUT** |

**核心规律：** 中场核心OUT的lambda修正幅度(10-15%)大于边锋OUT(5-8%)。凯塞多3场3首发的缺阵导致厄瓜多尔中场完全瘫痪，市场却只反应了5%不到的修正——这是模型vs市场15pp偏差的根源。

**数据源流程固化：**
```text
① 用户提供数据 → 先看是不是同时包含「固定奖金页」和「特征分析页」
② 如果只有固定奖金页 → 要求用户补充特征分析页HTML
③ 两个页面都有 → 按步提取伤停/历史/射手/积分榜
④ 特征分析页的伤停数据直接输入lambda修正系数
```

**⚠️ 彩果口径铁律（2026-07-05实战确认）：**
竞彩网的"彩果"栏只统计**90分钟常规时间**赛果。加时赛和点球大战的结果不计入竞彩开奖。
- 懂球帝战报和赛果页面通常显示含加时的最终结果
- 赛后校验模型时，必须以竞彩网90分钟数据为准
- 方向校验：使用竞彩彩果；晋级信息：使用懂球帝战报
- **两数据源口径不同，务必区分**

详见 `football-lottery-assistant` 的 `references/sporttery-cn-parsing.md`

### Step 2D: 懂球帝/凤凰网阵容数据获取（2026-06-30实战验证）

**必须获取双方完整阵容数据**，用于：
1. 核实伤停/可用球员（比竞彩网伤停一览更详细）
2. 估算阵容深度和轮换可能性
3. **构建文章叙事角度**（前队友对决、身价差距、关键对位）

#### 数据来源（按优先级）

| 来源 | URL模式 | 可用性 | 注意事项 |
|------|---------|--------|---------|
| **懂球帝** | `https://www.dongqiudi.com/team/{teamId}.html` | ✅ 首发优先 | web_extract可能返回空，需用户粘贴或browser工具 |
| **凤凰网** | 搜索"<队名> 世界杯大名单" | ✅ 备用 | 适合非洲/冷门球队 |
| **Wikipedia** | 2026世界杯球员名单页面 | ✅ 数据全 | 英文名对照 |

#### 需提取的关键字段

每队提取：主教练(国籍/年龄/风格) → 球员按位置分组(前锋/中场/后卫/门将) → 每人：俱乐部/年龄/出场数/进球/助攻/身价

#### 身价数据在模型中的使用

- 总身价比 → 品牌溢价公式的一部分：`品牌溢价 = min(20, (排名差÷10)×2 + log10(身价比)×3)`
- 身价集中度 → 依赖少数球星的球队更易被针对性防守

#### 叙事角度提取（直接用于文章）

| 对比维度 | 示例（英格兰vs刚果金） |
|---------|---------------------|
| **身价对比** | €13.6亿 vs €1.2亿，差10倍 |
| **联赛背景** | 22人踢英超 vs 3人踢英超 |
| **老队友对位** | 万-比萨卡(西汉姆) vs 拉什福德(曼联) — 前曼联队友 |
| **教练风格** | 图赫尔(防反德国派) vs 迪沙比(非洲务实派) |
| **大赛经验** | 英格兰近年大赛常客 vs 刚果金时隔52年重返 |
| **核心依赖** | 凯恩12球 vs 维萨3球(占全队75%) |

必须核实的三项：
- 比赛场地 → 官方赛程（FOX/FIFA）
- 天气预警 → 雷暴/极端天气
- 伤病名单 → "截至发稿时"

### Step 4: λ值估算（含动态校准）

⚠️ **推荐使用"双方法λ估算"（2026-06实战验证），单一方法偏差可达23pp。**

#### 方法1: 实际数据法（从xG代理开始）

```python
# xG代理公式（基于近10场或小组赛数据）
xg_for = 场均进球 × 0.92
xg_against = 场均失球 × 1.08

# 淘汰赛修正
#   强势方(目标"90分钟解决"): 进攻×0.9, 防守×0.9
#   弱势方(目标"不输拖入加时"): 进攻×0.5~0.6, 防守×0.75~0.85
#   实力接近淘汰赛: 双方×0.85~0.95

# 伤停修正: 核心球员OUT → λ下调5~15%（见Step 2C伤停表）
# 状态修正: W+0.08λ/场, D+0.02λ/场, L-0.05λ/场, 上限±0.25

# λ公式（中立场地, 主场修正=0）
lambda_home = (xg_for_home_adj + xg_against_away_adj) / 2 + form_home
lambda_away = (xg_for_away_adj + xg_against_home_adj) / 2 + form_away
```

#### 方法2: 市场反推法（从赔率开始）

```python
fairH = (1/hOdds) / (1/hOdds + 1/dOdds + 1/aOdds)
fairA = (1/aOdds) / (1/hOdds + 1/dOdds + 1/aOdds)
lambda_home_raw = 0.4 + fairH * 3.2   # 钳制[0.3, 3.5]
lambda_away_raw = 0.2 + fairA * 3.2   # 钳制[0.1, 2.5]

# 淘汰赛 + 伤停修正（注意：市场已部分定价，修正幅度减半）
lambda_home = lambda_home_raw × KO_factor × injury_factor
lambda_away = lambda_away_raw × KO_factor × injury_factor
```

#### 综合λ（推荐）

```python
# 双方法平均，互相校验
LAMBDA_HOME = (lambda_home_method1 + lambda_home_method2) / 2
LAMBDA_AWAY = (lambda_away_method1 + lambda_away_method2) / 2

# 如果两法偏差>0.5，说明市场定价或数据存在显著问题，偏向xG法
if abs(lambda_home_method1 - lambda_home_method2) > 0.5:
    LAMBDA_HOME = lambda_home_method1  # 偏向xG实际数据法
```

#### 主客场分离λ校正（v2.4新增 — 防止"排名惯性"误判）

⚠️ **不可忽略的问题：** 球队的排名≠主场战斗力。部分球队是"客场龙"（主场胜率远低于客场），市场容易按排名惯性高估其主场λ。

**实战案例（2026-07-05 韩职 首尔FC vs 仁川联）：**

- 仁川排名第6，但客场85.7%不败(3胜3平1负)
- 市场按排名给首尔主场过高估值
- 主客场分离后：首尔λ从1.95→1.71，仁川胜Edge从+1.8→+6.6pp
- **方向判断完全反转！**

**校正方法：**
```
不要直接用赛季场均数据算λ。必须分别计算主场和客场数据。

主场比赛的主队λ = (主场进攻xG + 客队客场防守xG) / 2 + 主队形式修正
客场比赛的客队λ = (客队客场进攻xG + 主队主场防守xG) / 2 + 客队形式修正
```

**使用原则：**
- 有主场/客场分离数据的，必须用分离计算
- 只有赛季总数据的，标注"⚠️ 缺乏主客场分离数据"
- 亚洲联赛（K联赛、J联赛等）主客场差异可能比欧洲联赛更显著

### Step 5: 比分EV计算（v1.4新增 — 价值量化核心）

```python
# 计算每个比分的期望价值
score_odds = {
    (1,0): 7.20, (2,0): 5.50, (2,1): 7.25,  # 从竞彩网比分盘获取
    (0,0): 16.00, (1,1): 10.00,  # 平局比分
    (0,1): 25.00,  # 客胜比分
}

ev_scores = []
for (h, a), prob in score_probs.items():
    odds = score_odds.get((h, a))
    if odds and prob > 0.005:
        ev = prob * odds - 1
        ev_scores.append((h, a, prob, odds, ev))

ev_scores.sort(key=lambda x: -x[4])  # 按EV降序
```

**EV阈值：**
- EV > +0.50 → 强价值（市场严重低估该比分）
- EV > +0.10 → 中价值（可小注博冷）
- EV > 0.00 → 弱价值（正期望但薄利）
- EV < 0.00 → 无价值（市场定价过高）

**实战验证（2026-06-29德国vs巴拉圭）：**
0-0 @16.00 模型概率8.0% vs 市场隐含6.2% → EV+0.29
淘汰赛弱队摆大巴90分钟拖点球，比市场定价的概率高2pp。

### ⚠️ 泊松模拟陷阱（2026-07-01实战发现）

**错误示范（循环体永远不执行）：**
```python
t = 1.0              # ❌ 初始值=1, while t<1 直接跳过
while t < 1:
    t -= math.log(1 - random.random()) / lam
    if t < 1: gh += 1
```

**正确写法（从0开始累加间隔时间）：**
```python
t = 0.0              # ✅ 从0开始
while True:
    t += -math.log(1 - random.random()) / lam
    if t >= 1.0: break
    gh += 1
```

原理：泊松过程的到达间隔时间服从指数分布。从比赛开始时刻t=0开始累加，每次跳跃一个指数间隔，直到超过比赛时长（90分钟=1.0单位）。用Knuth乘法法也可以（见 `scripts/mc-simulation.py` 的 `psample()`）。

验证方法：λ=1.73时，10万次模拟应产出约60%主胜（不是100%的0-0）。

### ⚠️ 数据源时效性陷阱（2026-07-01实战验证）

**Wikipedia小组赛数据可能过时：** Wikipedia的小组积分榜页面仅更新到页面说明中的日期（通常页首注有"Updated to match(es) played on YYYY-MM-DD"）。当你看到的日期早于当前对话日期时，该页面的数据**不含最近几天的比赛结果**。

**典型案例（2026-07-01 西班牙vs奥地利模型）：**
- 使用Wikipedia早前数据→假设西班牙"三战全胜"→ λ=1.976，胜率69.6%
- 实际西班牙2胜1平→ λ=1.623，胜率64.7%
- **偏差5pp，纯粹因未核实完整小组赛数据**

**核实流程：**
1. 先检查Wikipedia页面顶部的"Updated to matches played on"标注
2. 如果标注日期早于当前日-2天，必须从懂球帝、竞彩网赛果等补充最新完整比赛结果
3. 小组赛末轮比赛最容易遗漏，需特别关注
4. 小组赛数据（场均进球/失球）直接决定λ精度

**核心原则：** 不凭FIFA排名或球队名气脑补小组赛战绩。"世界杯1"≠"小组三战全胜"。每队小组战绩必须逐场核实再输入模型。

### 竞彩国内联赛定价特点

国内联赛的竞彩定价效率远高于世界杯：

1. **比分单关几乎全部负EV** — 2026-07-05验证：5场K联赛+3场瑞超，**所有比分EV均为负**
2. **让球盘效率高** — 让球-1/让球+1的定价偏差<5pp
3. **唯一正EV来源** — 主客场认知偏差（市场按总排名惯性定价，忽略主客场分离数据）
4. **凯莉机会少但集中** — 当Edge出现时通常在+6~18pp范围内，比世界杯的+3~10pp幅度更大
5. **⚠️ 超低赔率过热信号（v2.7验证）** — 蔚山@1.36→1-1平光州
   - 赔率<1.40时爆冷概率激增（8场校验中蔚山@1.36是最大冷门之一）
   - 规则：odds<1.40 → 自动标记🔴过热预警，热门胜率-2pp给平局+客队

  强队胜率: 原XX% → XX% (±XXpp)
  弱队胜率: 原XX% → XX% (±XXpp)

Edge变化:
  强队Edge: 原XXpp → XXpp （↑/↓/→）
  弱队Edge: 原XXpp → XXpp （↑/↓/→）

修正后核心判断:
  市场定价基本合理（差距<3pp） → 无显著价值信号
  市场定价仍有偏差（差距3-8pp） → 弱价值，可考虑

#### 重要警告

- ⚠️ **"被低估有Edge ≠ 弱队能赢"** — 奥地利+16pp Edge没爆冷，加拿大+10pp Edge修正后只剩+2pp。Edge不是冷门信号，是赔率价值信号。
- ⚠️ **小样本偏差** — 3-6场的校准样本有限，单场偏差（如比利时内讧）可能过度影响修正方向。连续收集更多场次再确认。

## 对比分析实战经验（2026世界杯 11场验证）

### 系统性偏差规律

外部文章（Opta/媒体）vs 后台模型的偏差呈规律性：

| 场景类型 | 胜率偏差 | 比分偏差 | 典型案例 |
|---------|---------|---------|---------|
| 强vs弱（70%+） | ≤3pp | 偏高1球（推3-0实际2-0更高） | 英格兰vs加纳 |
| 中等差距（60-70%） | ≤3pp | 偏高1球（推2-0实际1-0更高） | 哥伦比亚vs刚果金 |
| 接近对决（40-55%） | **+10~17pp** | 严重偏高（推3-0实际0-1最高） | 巴拿马vs克罗地亚 |
| 已出线球队对决 | +5-10pp | 严重偏高（推0-3实际1-1最高） | 突尼斯vs荷兰 |

**核心规律：**
1. 外部文章比分预测系统性偏高1球——模型首推1-0/0-1，文章推2-0/3-0
2. 平局概率被系统性忽略——模型给出20-28%平局，文章几乎不提
3. 弱队进球概率被低估——λ=0.68时进球概率≈49%，文章写成"零封"
4. 品牌溢价在接近对决中影响最大——62位排名差可导致+17pp偏差
5. 已出线球队轮换折扣被严重低估——模型首推1-1，文章推0-3/0-4

### 四关比分过关优化

模型首推比分四关联合概率 vs 叙事驱动方案：
- 模型方案（全取最高概率比分）：0.033%（1/3,039）
- 叙事方案（选"有故事性"的比分）：0.008%（1/12,438）
- **概率差距4倍**——每场差4-6pp，乘法叠加后差距巨大

**过关策略原则：**
- 选概率最高的比分，不选"最有故事性"的比分
- 1-1平局比分赔率通常是客胜2-3倍，概率损失<1pp但赔率翻倍→性价比最优
- 大2.5球概率>50%时考虑2-2等高比分选项
- 已出线球队对决大概率低比分（1-1或0-1），不是大屠杀

### 品牌溢价计算公式
```
市场隐含概率 = (1/赔率) / Σ(1/各赔率) × 100%
品牌溢价 = 模型概率 - 市场隐含概率
```

- |溢价| < 5pp → 无价值信号
- |溢价| 5-10pp → 轻度偏差，可小注
- |溢价| 10-20pp → 显著偏差，标准仓位
- |溢价| > 20pp → **极端偏差，高价值信号**

## 📊 多场综合方案中的投注框架（核心方法论）

当用户要求"比分串关推荐"或"投注方案"时，输出需要基于以下三层过滤：

### 比赛分层

| 层级 | 特征 | Edge阈值 | 策略 |
|:----|:-----|:--------:|:-----|
| 🟢 **主攻场** | 模型+市场一致且有EV | Edge>+3pp | 主仓,可做串关基石 |
| 🟡 **陷阱场** | 方向稳但赔率无价值 | Edge<-3pp | 不碰胜负,只玩比分 |
| 🔵 **利润核心** | 认知差最大 | Edge>+8pp | 博冷仓,高赔率错配 |

### EV筛选优先于概率排序

```python
# ❌ 错误：按概率排序——可能选了热门陷阱
# ✅ 正确：按EV排序——选出概率×赔率最优选项
```

实战原则：法国0-3(EV+6.98)很诱人但概率仅11.4%，0-2(16.4% EV+3.76)才是主轴。**高赔率≠高权重**。

### 加权分配（比分4串1）

| 层级 | 注数 | 单注权重 | 占比 |
|:----|:----:|:--------:|:----:|
| 核心路径 | 2 | 25-30单位 | 50-60% |
| 放大路径 | 2 | 10-15单位 | 20-24% |
| 防守路径 | 2 | 5-12单位 | 16-20% |

### 临场修正

盯三个信号：墨西哥赔率↓加仓↑转防守、法国≤1.15替换0-3、巴西-1.5加2-0权重。详见 `references/dynamic-ev-calculator.md`。

### 关键交易纪律

- **高赔率≠高权重**：法国0-3(EV+6.98)≠重仓，0-2(16.4%)才是主轴
- **不要碰陷阱场胜负**：法国胜@1.19 Edge-4.9pp，买了给庄家送水
- **联合概率不是加法**：每场覆盖率乘积≠赌注覆盖相加
- **比分4串1是娱乐，真正价值在单关**：巴西胜Edge+9.2pp

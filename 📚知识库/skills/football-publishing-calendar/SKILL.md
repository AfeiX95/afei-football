# 阿飞说球 — 每日发文日历管理

## 定位

此技能管理「阿飞·赛博聊球」头条号的**每日发文决策**。不覆盖怎么写文章（那是 `football-match-preview-pipeline` 和 `football-match-preview-article` 的事），而是覆盖**什么时候发、发什么内容、发多少篇**。

## 总原则

- **质量 > 数量** — 单日最多3篇，达到上限就休息
- **时间窗口优先** — 每个时段有最适合的内容类型
- **最后一个窗口不发深夜** — 冷启动需要活跃用户

---

## 每日发文窗口

| 窗口 | 时间 | 内容类型 | 说明 |
|:----|:----|:---------|:-----|
| **⭐ 主力篇** | **12:30** | 今日最佳场次的深度前瞻 | **全天最重要窗口** — 流量最大、数据钩子最清晰 |
| **凌晨场前瞻** | 16:30 | 次日00:00-06:00开赛场次的前瞻 | 提前发文，给用户时间阅读和思考 |
| **赛后复盘/明日预热** | 20:30 | 当日赛果复盘 / 次日重点场次预热 | **最后一个窗口，发完即止** |

### ⚠️ 深夜不发文铁律

> 发完20:30这篇就不要再发了。**避免深夜发文无人看**——冷启动需要活跃用户在线互动，23:00后发布的内容几乎不可能进入流量池。
>
> 允许的例外：已排好定时发布的稿件（非立即发布）。

## ⭐ 12:30 主力篇窗口

### 定位

**全天最重要的发文窗口。** 主力篇是当日流量主力，选今日最热门的场次做深度前瞻。与16:30凌晨场前瞻、20:30复盘不同，主力篇选择的是**当日白天到晚间黄金时段开赛**的核心场次。

### 触发条件

每天12:30，检查**今日竞彩所有场次**，选出适合做主力篇的比赛。

| 选场优先级 | 条件 | 说明 |
|:----------|:----|:-----|
| 🥇 首选 | 豪门对决 / 德比 / 榜首大战 | 流量最大，最值得投入全流程 |
| 🥈 次选 | 排名差距明显 + 数据钩子清晰 | 如第1 vs 第5，赔率差异明显的场次 |
| 🥉 备选 | 单关场次 / 高赔率争议场次 | 单关有独立流量入口，高赔率引发讨论 |
| ❌ 不选 | 中午前已开赛的场次 | 读者没有操作空间 |
| ❌ 不选 | 无数据钩子的普通场次 | 凑合写会掉粉 |

### 发稿前检测

```text
① 拉取竞彩网赛程（首选网易彩票 `sports.163.com/caipiao/match/football/jczq` 或 500.com `trade.500.com/jczq`）
② 列出今日所有场次（按开赛时间排序）
③ 筛选适合做主力篇的场次：
   - 开赛时间在 14:00-22:00 之间（读者有足够时间阅读和下注）
   - 有明确的看点（排名差距/H2H焦点/德比/保级战/争冠战）
   - 优先选 单关场次
④ 选择最佳场次 → 按 `football-match-preview-pipeline` 全流程写文
⑤ 检查 `I:\\阿飞说球\\{今日日期}/` 是否已有该场次内容（避免重复劳动）
```

### 发文时间线

| 时间 | 动作 | 说明 |
|:----|:----|:-----|
| **12:30** | **发文** | 主力篇发布，开始冷启动 |
| 14:00 | 冷启动期 | 初始流量推荐 |
| 17:00 | 二级推荐池 | 如数据好，进入更大流量池 |
| 21:00 | 推荐峰值 | 晚间流量高峰 |
| 22:00(工作日) / 23:00(周末) | 封盘 | 文章阅读转化截止 |

### 延迟执行处理 — 当12:30主力篇cron未按时执行

如果12:30的主力量cron在晚于计划时间才执行：

| cron实际执行时间 | 建议动作 |
|:----------------|:---------|
| 12:30-14:00 | ✅ **正常执行** — 仍在冷启动窗口内，写入全流程 |
| 14:00-16:00 | ⚠️ **可执行但降速** — 冷启动期已损失部分，但仍可发。全流程跑完即可 |
| 16:00-18:00 | 🔴 **检查已有内容优先** — 如有已生成文章，直接推荐发布；如无，跑精简版（仅核心数据+模型，不跑14维全流程） |
| 18:00-20:00 | 🔴 **仅推荐已有内容** — 不建议从零写新文章，比赛可能已开赛 |
| 20:00之后 | ❌ **放弃主力篇** — 今日场次均已开赛或临近开赛，已无意义。输出场次汇总供参考即可 |

**原因：** 主力篇需要读者有至少2-3小时阅读和操作时间。距开赛不足2小时才发文，读者来不及消化，转化率极低。

### 主力篇文章特殊要求

- 主力篇应使用**完整14维模型**（最强的内容质量）
- 文章开头应有「今日焦点」视觉标注
- 发文后必须：Git commit + 报告输出路径
- 如果当天比赛少或无比赛，发文提醒应输出：「今天比赛少，建议降为1篇或休息，保质量不保数量」

## 16:30 凌晨场前瞻窗口

### 触发条件

每天16:30，检查**次日北京时间 00:00-06:00** 开赛的场次。

| 当前日 | 截止时间 | 说明 |
|:------|:--------|:-----|
| 周一至周五（工作日） | **22:00** | 16:30发还有约5.5h窗口 |
| 周六至周日（周末） | **23:00** | 16:30发还有约6.5h窗口 |

### 检测流程

```text
① 拉取竞彩网API（一次性全量）
② 解析营业日，在 subMatchList 中逐一检查：
   - matchTime 在 00:00-06:00 之间
   - matchDate 为明日
   - matchStatus = 'Selling'
③ 如果检测到凌晨场：
   → 文章开头加紧急提醒："⚠️ 凌晨场XX点封盘，现在发还有X小时窗口"
   → 按全流程撰写文章 → 立即输出
④ 如果无凌晨场：
   → 报告"今日无凌晨场，可以休息或准备明天的内容"
   → 检查是否有其他可发内容（次日预热/数据复盘）
```

### 凌晨场文章特殊要求

- 文章开头第一段：加粗紧急提醒，写明封盘时间和剩余窗口
- 发文后必须：Git commit + 报告输出路径

## 关键实战经验（2026-07-24 验证）

### ① 生成内容优先检测 — 避免重复劳动

凌晨场前瞻可能已在**午夜准备阶段**（00:00-01:00前一日）提前完成。16:30 cron 执行前，**必须先检查是否有已有内容**：

```text
① 检查 `I:\阿飞说球\{明日日期}/` 目录下是否存在头条版HTML
   搜索文件名中的中文队名（注意API和文件名可能用不同译名）
② 如果存在：
   → 跳过全流程，仅验证内容是否完整
   → 输出提醒："已有生成内容，可直接发布"
   → 更新Git
③ 如果不存在：
   → 按全流程从零开始
```

**文件命名译名差异陷阱：** 竞彩网API返回的中文队名（如`雅罗`、`韦斯特罗斯`）可能与文件命名（如`芬超雅罗vs塞伊奈`、`瑞超瓦斯特拉斯vs奥尔格里特`）不一致。搜索既有文件时，**不要仅依赖API队名**，改用更宽泛的搜索：
- `search_files(target='files', pattern='雅罗*')` → 可能匹配`芬超雅罗vs塞伊奈*`
- 直接 `ls /i/阿飞说球/YYYYMMDD/` 全量浏览


### ② 延迟执行处理 — 当cron实际运行时间远晚于计划窗口

如果cron实际执行时间与计划窗口差距 > 1小时（如16:30窗口在21:00才执行）：

| 当前时间 | 建议动作 |
|:--------|:---------|
| 16:30-18:00 | ✅ 正常写入全流程，仍有3-5h购买窗口 |
| 18:00-20:00 | ⚠️ 检查是否有已有内容。有→直接发布提醒；无→写精简版（不跑完整模型） |
| 20:00-21:30 | 🔴 **已有内容优先**。如有已生成文章，直接推荐发布；如无，不建议跑全流程（来不及） |
| **21:30-22:00** | 🚨 **极端紧急** — 检测到内容即推荐立即发布；未检测到内容则输出快速通知供用户手动决策 |
| 封盘后 | ❌ 已无意义，通知"凌晨场已封盘，准备20:30窗口内容" |

**原因：** 一篇完整的14维前瞻从数据采到文章生成需20-40分钟。离封盘不足1小时时，全流程跑完读者已无操作空间。


### ③ 封盘前 < 1小时紧急模式

当封盘 < 60分钟时，原流程③中的"按全流程撰写文章"应替换为：

```text
③ 如果检测到凌晨场，且距封盘 < 60分钟：
   a. 优先检查 `I:\阿飞说球\{明日日期}/` 是否有已有内容
   b. 如有：直接推荐发布已有内容，输出紧急提醒
   c. 如无：
      - 输出简洁的双赛概览（无需跑完整模型）
      - 格式：场次信息 + 关键数据（排名/伤停/H2H亮点） + 概率判断
      - 提醒"时间紧迫，建议手动补充或直接复制发布"
   d. 紧急提醒模板：
      ⚠️ 今日XX点封盘！当前距封盘仅剩约XX分钟！
      凌晨场归属今日销售期，再不发就来不及了！
```

### ⑤ Tavily搜索间歇性失效处理

Tavily（`web_search` / `web_extract`）在cron运行中偶发 `[WinError 10054] 远程主机强迫关闭了一个现有的连接。` 错误。

| 症状 | 规律 | 应对 |
|:----|:----|:-----|
| 部分搜索成功，部分失败 | 中文关键词成功率 > 英文关键词；请求越频繁越容易触发 | **先试中文查询**，失败再试英文。不要连续大量搜索——在两次搜索间做其他处理 |
| `web_extract` 完全失败 | URL级别失败，多个URL同时挂 | **改用 `browser` 工具** 替代提取。2026-07-25验证：`browser_navigate` + `web_extract` 对捷报比分网有效 |
| 搜索能返回url但`web_extract`对目标页失败 | 目标页JS渲染或Cloudflare拦截 | 利用搜索结果的`description`字段——JSON-LD格式的比赛摘要常包含比分（如ESPN搜索结果显示"Västerås 2-0 Örgryte (25 Jul, 2026) Final Score"） |

**通用规则：** 不要在一次搜索失败后就放弃该联赛。重试1-2次或切换查询语言/站点。

### ⑥ 凌晨场前瞻预生成 → 20:30窗口的衔接

常见场景：凌晨场前瞻在**前一天晚上**已生成（`20260725/`目录内容都是7月24日创建的），但当时并未发布到头条号。到20:30窗口时：

1. 这些比赛已经完场，可以查赛果
2. 但凌晨场前瞻本身已经是旧内容（发布前就已过期）
3. **正确做法：** 以赛后复盘角度使用已有内容 + 查赛果数据。如果赛果⚡无大爆冷 + 时间过晚 → 按常规决策休息
4. 如果一定要发：用「昨夜今晨」混合格式，同时覆盖赛果回顾+明日预热，而非单独发一篇复盘

> ⚠️ **不要因为"内容已生成但未发"就觉得必须发。** 凌晨场前瞻的时效性在赛后就已失效，发布旧内容比不发更伤账号。

## 20:30 赛后复盘/次日预热窗口

### 四步决策框架

每轮20:30窗口按以下顺序评估，**四步走完才能决策**：

```text
Step 1: 查当日赛果
        ↓
Step 2: 评估爆冷/数据亮点
        ↓
Step 3: 查今日已发文数
        ↓
Step 4: 看当前时间 → 最终决策
```

#### Step 1: 查当日赛果

> ⚠️ **竞彩网API重大限制：** 竞彩API只返回`matchStatus='Selling'`的场次（仍在销售的比赛）。**已完场的比赛不会出现在API中。** 如果API返回0场或少量场次且状态均为Selling，说明这些比赛尚未开赛，不是已完场。
>
> ⚠️ **凌晨场判断：** 竞彩营业日`businessDate=当日`但`matchDate=明日`且`matchTime=00:00-06:00`的场次是**今晚午夜至明晨**的比赛，不是今日上午已完场的比赛。20:30窗口查不到已完场结果时，先确认API返回的是不是凌晨场——是则跳过复盘。

常用数据源（按可靠性排序，2026-07-24验证版）：

| 源 | 获取方式 | 适用联赛 | 实际可靠性 |
|:--|:---------|:---------|:----------|
| 网易彩票 `sports.163.com/caipiao/match/football/jczq` | `web_extract` | 全赛程 | ✅ **最可靠** — 文本可读，含赔率/排名/场次编号/状态(完场/未开赛) |
| 500.com `trade.500.com/jczq` | `web_extract` | 全赛程 | ✅ 文本可读，含赔率/排名/单关标记 |
| 网易彩票 `sports.163.com/caipiao/league/football/581` | `web_extract` | 韩国K联赛 | ✅ 文本可读，有比分即完场 |
| Chosun Biz `biz.chosun.com/en/en-sports/` | `web_extract` | 韩国K联赛 | ✅ 英文战报含详细事件 |
| **Web搜索** `web_search` | `web_search` | 全球 | ✅ 用日期+联赛名查询，最通用 |
| **AiScore移动版** `m.aiscore.com/tournament-...` | `web_extract` / `browser` | 全球 | ⚠️ **Cloudflare阻拦** — 2026-07-25验证`browser`也被拦，建议放弃或用其他源 |
| **FootballAnt** `footballant.com` | `web_extract` / `browser` | 全球 | ❌ **Cloudflare阻拦** — 无法访问，放弃 |
| Wikipedia联赛页 | `web_extract` | 各联赛 | ⚠️ 数据有延迟（通常滞后数天） |
| LiveScore `livescore.com` | `browser` | 全球 | ⚠️ **404风险** — 2026-07-25验证赛程页404；主站首页可加载但赛果JS渲染，akcessibility tree看不到得分 |
| **捷报比分网** `www.nowscore.com` | `browser` | 全球（含北欧/亚洲） | ✅ **推荐备选** — 浏览器加载后可见热门作者推荐的比分结果（如`00:00 雅罗 2-1 塞伊奈约基`）。搜索结果页的"热门作者"栏目会列出近期完场比分。首页内容可`web_extract`获取文本版，但详细的比分表需要browser获取。2026-07-25验证有效。 |
| **Flashscore** `flashscore.com.ng` | `browser` | 全球 | ❌ `web_extract`返回空(JS渲染)。改用`browser`可加载，但需注意bot检测。2026-07-25验证。 |
| **7M体育** `data.7m.com.cn/result_data/` | `web_extract` | 全球 | ❌ **返回空或阻塞，不可靠** |

**检查步骤：**
1. 先查竞彩网API，区分今天是否有完场vs全部是凌晨场（未开赛）
2. 如有已完场场次（matchTime早于当前时间、非凌晨场）→ 用AiScore/WebSearch查比分
3. 如API只返回凌晨场（今晚午夜开赛）→ Step 1结束，无当日赛果可复盘

**备用方案（当web_extract都不工作时）：**\n- `web_search(query="[联赛名] results [YYYY-MM-DD]")` 最通用\n- 搜索时带日期限定词如 `"July 24 2026" "Allsvenskan" score`\n- **语言策略：** 中文联赛名+中文日期关键词（如"韩职 浦项铁人 全北现代 2026年7月25日 比分"）的Tavily搜索成功率高于英文搜索，因为Tavily覆盖中文站点更好。先试中文，不行再试英文。\n- **ESPN搜索描述技巧：** 搜索结果的`description`字段常包含比赛摘要和比分（JSON-LD格式），即使页面本身JS渲染。查询 `site:espn.com "final score" "[联赛]" "[日期]"` 可能直接从摘要拿到最终比分。\n\n> ⚠️ **注意区分「今日比赛」与「最近几轮比赛」：** LiveScore概览页显示的"赛果"可能是最近各轮的混合结果，不全是今天的。必须用比赛日期做筛选。

#### Step 2: 评估爆冷/数据亮点

| 爆冷等级 | 判断标准 | 建议动作 |
|:--------|:--------|:---------|
| ⭐⭐⭐ 大爆冷 | 强队主场输给中下游/补时绝杀/5轮不胜等戏剧性事件 | **趁热度发——赛后复盘是高流量内容** |
| ⭐⭐ 小冷门 | 强队平弱队/点球罚丢/VAR取消绝杀 | **有价值但仍需考虑时间窗口** |
| ⭐ 常规结果 | 排名相近的正常比分 | **不单独发复盘，可考虑明日预热** |

**复盘的切入点（高流量框架）：**
- 「XX崩盘！X轮不胜+补时点杀，争冠格局一夜变天」
- 「XX点球宴客，XX主场翻车——这轮联赛有多离谱？」
- 「从XX的X连败看本赛季的X大趋势」

#### Step 3: 查今日已发文数

```bash
# 统计今日创建的所有文章文件（跨越多个日期目录）：
# 凌晨场前瞻可能已存入明日文件夹（20260725/），20:30查时容易遗漏
today=$(powershell.exe -Command "Get-Date -Format 'yyyyMMdd'")
find /i/阿飞说球 -newer /i/阿飞说球/$today -type f \( -name "*.html" -o -name "*.md" \) 2>/dev/null | wc -l
# 注意：find -newer 按修改时间过滤，今日生成的文件都会被统计
# 如果无法用 find（如git-bash find不支持-newer），改用更简单的：
ls -la /i/阿飞说球/$today/*.html /i/阿飞说球/$today/*.md 2>/dev/null | wc -l
ls -la /i/阿飞说球/$((today+1))/*.html /i/阿飞说球/$((today+1))/*.md 2>/dev/null | wc -l
```

**进阶：区分「内容」vs「文件格式」：** 一篇比赛分析通常对应3个文件（14维深度前瞻.md + 头条版.md + 头条版.html）。上面统计的是文件数，不是文章数。评估"今日已发几篇"时应按"内容标题"去重：

```bash
# 粗略按内容标题去重（去掉14维和头条版的重复）
ls /i/阿飞说球/$today/*.html /i/阿飞说球/$today/*.md /i/阿飞说球/$((today+1))/*.html /i/阿飞说球/$((today+1))/*.md 2>/dev/null \
  | sed 's/.*\///; s/_.*//' | sort -u | wc -l
```

| 内容数 | 结论 |
|:--------|:-----|
| 0-2篇 | 可以再发一篇 |
| **3篇或以上** | **建议休息，质量>数量** |
| 今日已发过赛后复盘类文章 | 不建议再发复盘（同类内容重复） |

#### Step 4: 看当前时间 → 最终决策

| 当前时间 | 决策 |
|:--------|:-----|
| 20:30-21:00 | ✅ **最优窗口** — 比赛刚结束，热度最高 |
| 21:00-22:00 | ✅ **可发** — 还在晚间流量期 |
| 22:00-23:00 | ⚠️ **谨慎** — 接近深夜，只有大爆冷才值得发 |
| **23:00之后** | ❌ **不要发** — 冷启动失败概率极高。素材留到明早补 |

#### 如果决定不发 / 无完场可复盘

- **常见场景：20:30窗口时今日竞彩场次均为凌晨场（未开赛）** → 直接休息，无需强发
- **有爆冷素材但时间已晚** → 记录爆冷素材 → 明日17:00窗口以"焦点战预热+昨日复盘"混合内容发出
- 回复用户：时间过晚，建议明早发

## 通用规则

### 内容类型选型

| 今日有 | 可用素材 | 适合发文类型 |
|:------|:--------|:------------|
| 多场当天比赛 | 已完成赛果 | 赛后复盘（选最大爆冷） |
| 次日有焦点战 | 赛前情报 | 次日预热/前瞻 |
| 两者都有 | 爆冷+焦点战 | 混合内容（"昨夜今晨"式） |
| 两者都没有 | — | **休息，不发** |

### Cron Job 执行约束

| ❌ 不可用 | ✅ 替代方案 |
|----------|-----------|
| `execute_code` | `terminal` 中运行内联Python |
| `delegate_task` | 单线程串行完成 |
| `clarify` / 提问 | 自主决策，合理默认值 |
| `workdir` 含中文 | 在command参数中内嵌 `cd /i/阿飞说球 &&` |

### 时间获取（Windows git-bash）

```bash
# ✅ 首选：简单 date 命令（无需-c flag，避免被cron安全策略阻拦）
date '+%Y-%m-%d %H:%M:%S %A'

# ✅ 备选：用 PowerShell 获取 Windows 本地时间
powershell.exe -Command "Get-Date -Format 'yyyy-MM-dd HH:mm:ss dddd'"

# ❌ 不可用：powershell.exe -Command 带复杂参数在cron中可能被安全策略拦住
# ❌ 不可靠：TZ=Asia/Shanghai 在 git-bash 中可能挂
TZ=Asia/Shanghai date '+%Y-%m-%d %H:%M:%S'
```

> ⚠️ **cron安全策略注意：** 如果cron配置了 `approvals.cron_mode: reject`，含有 `-e`, `-c`, `Script` 等标记的命令会被阻拦。`powershell.exe -Command` 属于高风险模式。`date` 命令不受影响，是cron中最可靠的获取时间方式。

### 文件路径（Windows git-bash）

终端内 `cd` 和 `ls` 可用 MSYS路径（`/i/阿飞说球`）。但在 `write_file` 和 `read_file` 中**必须用原生Windows路径**（`I:\\阿飞说球\\...`）。

# Football Injury Tracker 伤停与首发预测器

> 定位：自动化伤停数据采集+首发阵容预测
> 适用场景：每场比赛分析前的伤停评估阶段
> 搭配使用：14维评分卡（维度#3伤停影响 + 维度#6核心球员对位）

---

## 一、数据源

| 数据源 | 内容 | 更新频率 | 获取方式 |
|:-------|:-----|:---------|:---------|
| Transfermarkt | 伤病名单/停赛/复出时间 | 每日 | 爬虫 |
| 新球体育 | 伤停一览（基础版） | 赛前 | 爬虫（已有 titan_fetcher） |
| 懂球帝 | 阵容预测/伤停动态 | 实时 | API |
| Twitter/X | 随队记者首发预测 | 赛前2-4小时 | autocli |
| 俱乐部官网 | 官方伤停公告 | 不定期 | 爬虫 |

---

## 二、核心脚本

### 2.1 Transfermarkt 伤停抓取

脚本位置：`database/scripts/transfermarkt_injuries.py`

功能：
- 抓取指定球队的伤病名单
- 提取：球员名、位置、伤病类型、预计复出时间
- 输出 JSON 格式

```bash
python database/scripts/transfermarkt_injuries.py --team "Ulsan HD"
```

### 2.2 随队记者推特监控

脚本位置：`database/scripts/journalist_monitor.py`

功能：
- 通过 autocli 监控指定记者的 Twitter/X 账号
- 关键词过滤：injury, lineup, squad, training, 首发, 伤停
- 提取赛前首发预测信息
- 输出时间线格式

```bash
python database/scripts/journalist_monitor.py --team "Ulsan HD" --hours 24
```

### 2.3 首发阵容预测

脚本位置：`database/scripts/lineup_predictor.py`

功能：
- 基于近期首发记录 + 伤停数据 + 战术习惯
- 预测最可能首发11人（含阵型）
- 输出对比表：主队预测首发 vs 客队预测首发

```bash
python database/scripts/lineup_predictor.py --home "Ulsan HD" --away "FC Anyang"
```

## 三、伤停影响评估模型

### 3.1 球员价值分级

| 级别 | 定义 | λ修正量 | 示例 |
|:----:|:-----|:-------:|:-----|
| S级 | 核心射手/门将 | -0.15 ~ -0.20 | 蔚山法里亚斯（中锋） |
| A级 | 主力中场/中卫 | -0.08 ~ -0.12 | 蔚山欧德科特（中卫） |
| B级 | 轮换主力 | -0.03 ~ -0.05 | 普通主力 |
| C级 | 替补/青年队 | 0 ~ -0.02 | 替补球员 |

### 3.2 累积伤停修正

```
总伤停修正 = Σ(球员级别 × 位置系数 × 主场/客场权重)

位置系数：
- 前锋: 1.2（进球直接影响）
- 中场: 1.0（标准）
- 后卫: 0.9（防守影响略低）
- 门将: 1.3（最后一道防线）

主场权重: 1.1（主场球员缺阵影响更大）
客场权重: 0.9（客场球员缺阵影响略小）
```

### 3.3 首发预测置信度

| 信息来源 | 置信度 | 说明 |
|:---------|:------:|:-----|
| 俱乐部官方公告 | 95% | 最权威 |
| 随队记者首发预测 | 80% | 赛前2-4小时较准 |
| 训练照片推断 | 60% | 间接证据 |
| 历史首发推断 | 40% | 仅参考 |

## 五、与14维评分卡对接

| 评分卡维度 | 伤停数据对接 |
|:-----------|:-------------|
| #3 伤停影响 | 球员价值分级 × 累积修正 → 直接输入λ修正 |

## 六、注意事项

1. **时效性**：伤停数据赛前4小时最准，过早获取可能不准确
2. **随队记者选择**：不同球队的记者可靠性差异大，需建立记者可信度评级
3. **故意烟雾弹**：部分教练会在赛前释放虚假伤停信息，需交叉验证
4. **累积效应**：多人同时缺阵的影响大于单人缺阵的简单叠加

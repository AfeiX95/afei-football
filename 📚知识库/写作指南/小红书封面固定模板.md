# 小红书封面固定模板 v3.0（赛博数据终端 × 绿茵球场，2026-10-23 定）

> 骨架：**日期** + **「N 场足球赛事前瞻」** + **阿飞·赛博聊球**。v2（v1 深色胶囊）、v2.0（纯条纹球场 + 底部三格）保留为 `--cover-style v2 / dark / light` 备查。
> 代码真源：`scripts/xhs_card_d.py` → `cover_v3_html(data, wide=False)`；球场为内联 SVG 常量 `PITCH_SVG`，无外部图片、无 AI 生图。
>
> 2026-10-23 起另有一套可复用系统 `scripts/cover/`（AFEI Football Cover System v1.0）：三种模板（每日总览 / 单场深度 / 多场矩阵）× 两种比例（3:4、16:9），JSON 驱动、带质量自检，用法见 `scripts/cover/README.md`；本文件描述的是其中的「每日总览」骨架。

## 二、竖版结构（绝对定位，尺寸永不漂）

1. **顶栏**：`12 MATCHES // DATA CARD` ｜ 右 `阿飞 · 赛博聊球`
2. **日期块**：`10.23`（126px，点=绿圆）→ 下一行 `星期五 ｜ 10/23 17:00 起 跨夜`
3. **主标题**：`12 场足球` / `赛事前瞻`（84px，`N 场` 绿色）——**场数进标题**，这是 v3 的核心变化
4. **数据小行**：`12 场赛事 · 8 个开球时段 · 12 项联赛`
5. **口径行**：`公开数据 · 模型推演 · 风险校验`
6. **右侧竖排三张数据卡**（306px 宽，图标用简笔 SVG：球/钟/叠层）：`12 场 赛事拆解`、`8 段 开球时段`、`12 项 联赛覆盖`
7. **球场区**：920px 宽，顶部 600px 起
8. **分隔行**：`FOOTBALL —— DATA —— ANALYSIS`（绿色细线连缀）
9. **品牌区**：绿竖条 + `阿飞 · 赛博聊球`（50px）+ 下移一行 `用数据拆解比赛`
10. **脚注**：联赛全清单 ｜ `十二场，先看账，再看球`

横版：左列日期/标题/数据行 + 三张卡横排；右侧放大球场；底部品牌与脚注。

## 三、每日只换配置

`date` / `weekday` / `matches` / `slots` / `leagues` / `kick_day` / `tail`（全部来自 `cards_*.json`，`cover_config.json` 可复核）。

## 四、文案红线

- 不写方向、比分、概率、场次编号，不列逐场清单。
- 数据卡只放客观口径（场数/时段/联赛数），不放胜率、命中率。
- 不用 emoji；强调靠绿色数字、竖条与细线。
- 口径固定为 **公开数据 · 模型推演 · 风险校验**（不用「0 处主观臆测」这种绝对话）。

## 五、生成（pwsh；Chrome 需全权限）

```powershell
$env:XHS_HTML_TMP="I:\阿飞说球\state\tmp\xhs_html"
python -X utf8 scripts/xhs_card_d.py --input <cards.json> --out "<输出目录>" --cover
```

产出：`00_封面.png`（3:4）、`00_封面_16x9.png`、`00_封面_预览.png`。
样式：`--cover-style v3`（默认）/ `v2` / `v2-wide` / `dark`（v1）/ `light`（v1 浅色）。

## 六、验收四条

1. 360×480 缩略图下：日期、`N 场足球赛事前瞻`、`N 场` 数据卡、品牌四样可读
2. 右侧数据卡不压球场、球场不压标题
3. 竖版无重叠（重点看品牌行与分隔行）；横版无底部堆叠
4. 文本层扫禁用词 0 命中（比分/让球/盘口/赔率/主胜/客胜/模型/概率）

## 八、没采用的三件事（记录理由）

1. **队徽**：参考图里的 TORINO / MONZA 徽记属俱乐部商标，且需要按队逐张取图与压缩，稳定性差；改用文字队名 + 数据卡。
2. **AI 生成球场实景**：会带来中文错字与风格漂移，违反「资产固定、文字程序绘制」原则；球场保持矢量。
3. **球员剪影/看台实拍**：一是有版权风险，二是与「数据终端」定位不符。

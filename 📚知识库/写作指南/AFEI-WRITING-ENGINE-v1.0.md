## 一、总原则

阿飞公开稿采用双层内容轮换：

- **第一层：写作风格（A–H）**——决定文章怎么表达（口吻）。
- **第二层：文章结构（S01–S10）**——决定信息怎么组织（叙事顺序）。

风格和结构**独立选择、不固定绑定**（8 × 10 = 80 种理论组合，按素材选，不要求每种都用）。
所有写作必须服从数据真实性、分析逻辑和平台合规。**风格与结构的选择不得改变内部报告的方向与比分三档**（`check_report_consistency.py` 把关），也不得为了故事效果修改数据事实。

## 二、风格池（A/B 为日常基础，C–H 按素材触发）

| 代号 | 风格 | 核心 | 价值 | 目标占比 |
|:--|:--|:--|:--|:--|
| A | 老球迷观察型 | 口语、幽默、个人情绪 | 亲和力 | 20% |
| B | 数据分析师型 | 数据、逻辑、反向验证 | 专业度 | 20% |
| C | 悬念推理型 | 疑问、推理、逐层揭示 | 阅读吸引力 | 15% |
| D | 战术对抗型 | 阵型、对位、攻防博弈 | 专业深度 | 10% |
| E | 反常识纠偏型 | 质疑、验证、拆解误区 | 观点辨识度 | 15% |
| F | 故事叙事型 | 球队变化、人物、背景 | 情感连接 | 5% |
| G | 赛后复盘型 | 预测、结果、误差分析 | 长期信任 | 10% |
| H | 极简快评型 | 短句、重点、快速判断 | 更新效率 | 5% |

> 占比是内容规划建议，**不是平台数据验证过的最优解**；后续按阅读完成率、阅读时长、评论率、关注转化调整（`writing_engine.py --list` 会打印最近 20 篇实际占比）。

### C｜悬念推理型
先提出一个具体疑问，再用数据逐步找答案，让读者跟着推理。开头设问 → 中间逐步揭示证据 → 结尾给出阿飞判断。
适合：强强对话、连续交锋、定价与球队表现出现反差。
> 纽卡刚刚输给埃弗顿，三天后又要碰面。奇怪的是，回到主场以后，外界依然更看好纽卡。问题来了：这次真的是主场优势，还是上一场失利并没有改变双方的实力判断？

**边界**：悬念只能放在推理过程里，**不得隐藏关键事实**；每场的方向与「推荐比分」照常必写（R56），标题不得做无主语悬念（R58 标题党）。

### D｜战术对抗型
不只分析谁更强，而是分析双方的优势如何碰撞：控球与反击、高位逼抢与后场出球、边路进攻与边后卫防守、定位球攻防、中场控制权、关键球员对位。
适合：强强对话、风格冲突明显、战术差异大的比赛。
> 这场有个关键对位：主队边路推进不错，客队恰好又是边路防守容易出空当的球队。问题不是谁的整体实力更强，而是谁能先抓住对方的弱点。

**边界（硬）**：必须有实际比赛数据、阵型或战术资料支撑，**不能凭球队名气编战术**。`writing_engine.py` 要求 `--tactical-source` 写明资料来源才会触发 D。注意本仓库战术层数据仍是缺口（`open_items`「战术层与失球时间分布缺口」），没源就别选 D。

### E｜反常识纠偏型
拿一个大家普遍认可的说法，看数据是否真的支持。
常见选题：五场不败为什么仍不值得高看｜主场优势有时只是统计错觉｜交锋六连胜为什么未必有参考价值｜进球很多为什么效率反而不高｜排名靠前为什么近期攻防在下滑。
> 五场不败就代表状态好吗？未必。把对手强弱和主客场拆开之后，这五场可能没有表面看起来那么漂亮。

最贴合 AFEI 数据体系的一型；纠偏必须有数据，不许为反而反（人设「敢讲不同意见，但必须有证据」）。

### F｜故事叙事型
从球队的处境、变化和经历讲比赛：教练战术变化、伤愈复出、密集赛程、保级/争冠压力、低谷反弹。
> 十月份的美因茨，似乎有点奇怪。客场能赢球，回到主场却连续丢分。现在拜仁来了，留给他们解决问题的时间已经不多。

**边界（硬）**：故事必须来自可核实的公开信息（官方公告、主流媒体报道、比赛数据），**不许虚构更衣室情节**——无源编造会被头条判「不实内容」-70 分档（R58）。`writing_engine.py` 要求 `--story-source` 才会触发 F。

### G｜赛后复盘型
不只看预测对不对，更要解释为什么对、为什么错。固定四段：
1. 赛前判断是什么？
2. 实际比赛发生了什么？
3. 哪项数据支持或推翻了原先判断？
4. 哪个分析环节应该修正？

> 赛前我看好客队，结果主队赢了。比分错了只是表面，真正值得复盘的是赛前忽略了主队的边路推进效率。

**分层（R55）**：公开稿第 4 段只用读者话写「我赛前漏看了什么、下次会多看什么」；**模型参数怎么改**写进 `📚知识库/赛后校验/batchNN_calibration.md`，不进公开稿。这是阿飞最该长期经营的类型之一——很多账号只发预测，很少认真解释自己的错。

### H｜极简快评型
只讲最关键的两三条信息，不把简单比赛写复杂。
> 这场没什么复杂的。主队排名占优，但近五场只赢一场；客队进攻一般，防守却更稳。主队有主场优势，但还不足以让我无条件看好。

**篇幅规范（2026-11-07 用户拍板生效）**：
- **独立短图文 / 微头条**：正文控制在 **300–500 字**（文件名带 `_快评` / `_微头条` / `_短图文`，或跑 `python -X utf8 scripts/preflight.py <文章.md> --short` 走 300–500 字门禁）。
- **多场长文内嵌**：作为多场稿里「其余场次快评段」的写法（常配 S05 焦点主线），整篇仍走 800–1500 字门禁。

## 三、结构池（S01–S10）

| 代号 | 结构 | 叙事顺序 | 适合 |
|:--|:--|:--|:--|
| S01 | 反常现象型 | 反常数据 → 正常认知 → 数据拆解 → 异常原因 → 反向证据 → 阿飞判断 | 主客倒挂、排名与状态反差、攻守失衡 |
| S02 | 悬念递进型 | 提出疑问 → 第一条证据 → 第二条证据 → 意外发现 → 最终判断 | 强强对话、外界预期与表现矛盾 |
| S03 | 双方对照型 | 主队优势 → 主队隐患 → 客队优势 → 客队隐患 → 核心对抗 → 判断 | 强弱接近、双方各有特点 |
| S04 | 分类归因型 | 共同主题 → 案例一及原因 → 案例二 → 案例三 → 横向比较 → 总结 | 多场比赛、同一数据主题（≥2 场） |
| S05 | 焦点主线型 | 多场概览 → 核心比赛深拆 → 两场辅助对照 → 其余快评 → 核心观点 | 多场里有一场特别值得关注（≥3 场） |
| S06 | 结论先行型 | 先亮判断 → 最关键证据 → 补充证据 → 不利因素 → 修正判断 → 比分参考 | 观点鲜明、数据充分、读者熟悉 |
| S07 | 状态演变型 | 此前状态 → 近期变化 → 关键转折 → 当前问题 → 下一场的影响 | 连败反弹、换帅、伤员回归、密集赛程 |
| S08 | 交叉验证型 | 比较对象 → 共同对手 → 比赛表现 → 主客场修正 → 样本局限 → 判断 | 共同对手多、交锋资料丰富 |
| S09 | 风险拆解型 | 表面优势 → 三大风险 → 风险影响 → 哪些可化解 → 判断 | 热门占优但有明显隐患 |
| S10 | 论点反证型 | 初始观点 → 支持证据 → 反向证据 → 两边权衡 → 修正结论 | 模型与市场分歧、热冷争议 |

标题示例（仅示意句式，不是模板）：S01《美因茨主场四场不胜，客场却赢了四场》｜S02《纽卡刚输给埃弗顿，回到主场还能扳回来吗？》｜S03《马赛主场火力强，图卢兹客场为什么也不好惹？》｜S04《三支球队主场不胜，背后却是三个不同问题》｜S05《利物浦对阿森纳，深夜真正值得看的其实是这一场》｜S06《这场我更看好町田，但不认为它能轻松大胜》｜S07《连续五场零封之后，町田的防线还能撑多久？》｜S08《共同踢过四支球队，布兰和莫尔德到底谁更强？》｜S09《拜仁赢面不小，但美因茨有三个地方值得提防》｜S10《阿森纳八场只输一场，但这次我为什么不敢看得太高？》（标题仍受 R20 ≤30 字、R58 标点白名单约束）

**同一结构 × 不同风格**（以 S04 为例）：A 像老球迷聊天，先讲有趣的现象再分开调侃三支球队；B 逐一分析数据差异与攻防原因；C 设置疑问让读者逐步发现三个问题；E 纠正「主场一定占优」的认知。

## 四、选择流程（八步）

1. 读取比赛数据和资料（R48 管线：intel → books → market → audit → model_v3 → 内部报告）。
2. **独立完成每场的事实核查与分析**（方向 / 进球结构 / 比分三档先定死，R61③）。
3. 提炼这批比赛最有价值的内容角度 → 翻译成素材特征（见 §五）。
4. 选风格：`writing_engine.py --pick` 第一段。
5. 选结构：同一命令第二段（按适配分排序，近期用过只扣分）。
6. 检查最近 3 篇的结构与开头，尽量避免重复（脚本已自动扣分并给开头/结尾建议）。
7. 生成标题、正文、比赛判断和结尾（标题与开场最后写，R61④）。
8. 执行事实、逻辑、重复及平台合规检查：`check_report_consistency` → `preflight`（含「轮换」行）→ `check_dup` → `check_pub_safety`；通过后 `--record` 落账。

```bash
python -X utf8 scripts/writing_engine.py --features-help                 # 看素材特征表
python -X utf8 scripts/writing_engine.py --pick --matches 4 --feat anomaly,same_theme,fav_risk
python -X utf8 scripts/writing_engine.py --check "<文章.md>"             # 写完体检（preflight 也会带）
python -X utf8 scripts/writing_engine.py --record --article "<文章.md>" --style E --structure S04 --column 阿飞拆局
python -X utf8 scripts/writing_engine.py --list                          # 风格占比 / 结构使用 / 最近 3 篇
```

## 五、自动选择机制

### 5.1 素材特征（`--feat`，逗号分隔）

| 特征 | 含义 | 触发风格 | 加分结构 |
|:--|:--|:--|:--|
| `post` | 赛后复盘（`--stage post` 自动带） | **G（固定）** | S07 +1、S10 +1 |
| `tactical` | 风格冲突明显（**必须配 `--tactical-source`**） | D | S03 +2 |
| `counter` | 常识说法被数据推翻 | E | S10 +2、S01 +1 |
| `story` | 可核实的连续故事线（**必须配 `--story-source`**） | F | S07 +2 |
| `question` | 有一个具体疑问 | C | S02 +3 |
| `simple` | 简单比赛、数据差异不大 | H | S06 +1 |
| `anomaly` | 主客倒挂 / 排名与状态反差 / 攻守失衡 | — | S01 +3 |
| `balanced` | 强弱接近、各有特点 | — | S03 +3 |
| `same_theme` | 多场共享同一主题（≥2 场） | — | S04 +3 |
| `focus` | 多场里一场特别值得深拆（≥3 场） | — | S05 +3 |
| `strong_view` | 观点鲜明、证据充分 | — | S06 +3 |
| `form_change` | 连败反弹 / 换帅 / 伤员回归 / 密集赛程 | — | S07 +3 |
| `common_opp` | 共同对手多（S08 的前提） | — | S08 +3 |
| `fav_risk` | 热门有明显隐患 | — | S09 +3 |
| `split` | 模型与市场分歧 / 热冷争议 | — | S10 +3、S02 +1 |

### 5.2 风格选择逻辑
- 赛后 → G；否则在被触发的 C–H 里打分：`基础优先级（D5 / E4 / F3 / C2 / H1）+ 比例差×10 − 上篇同风格 2`，取最高。
- 没有任何特殊素材 → **A/B 交替**（看账本里上一篇 A/B 是谁）。
- 不机械按 A→B→C→D 循环，也不纯随机。

### 5.3 结构选择逻辑
- `总分 = 素材适配分 − 近期惩罚`（上一篇用过 −2.5，最近 3 篇用过 −2）；同分时最久没用过的优先。
- **素材为先**：如果某篇确实最适合 S04（适配 3 以上明显领先），惩罚后仍可能胜出——不为轮换强改成 S08。
- 硬前提：S04 需 ≥2 场、S05 需 ≥3 场、S08 需 `common_opp`。所有结构适配分都是 0 时脚本会提示「先回去找这批比赛真正值得讲的点」。

## 六、轮换管理规则

| 管理项目 | 执行规则 | 工程落点 |
|:--|:--|:--|
| A/B 基础风格 | 默认交替 | `--pick` |
| C–H 特殊风格 | 根据素材触发 | `--pick` |
| 文章结构 | 10 种按适配度选 | `--pick` |
| 结构重复 | 最近 3 篇尽量不重复 | 扣分 |
| 开头方式 | 连续 3 篇不能用相同套路 | `--check` 硬项 |
| 比赛分段 | 允许调整每场分析顺序；不许每场同一顺序 | `--check` 硬项「论证顺序流水线」 |
| 标题 | 不与上一期用同一种表达模式 | `--check` 软项 |
| 最终判断 | 必须来自逐场分析，不受结构影响 | `check_report_consistency` |

账本 `state/writing_history.json` 的 `engine` 段自动维护：`last_style / last_ab / last_structures / last_openings / last_ending / rotation_rule`。只有过 preflight 的稿才 `--record`。

## 七、内容去重检查（五个维度）

结构换了，文章仍可能读起来一样。`writing_engine.py --check`（并入 `preflight` 的「轮换」行，**目前只提示不阻断**）检查：

1. **开头去重**：开头套路连续两篇相同 → 第三篇必须换（硬）；命中「今天有几场 / 这一批 / 这几场里 / 共同点」老套路（软）；与最近 3 篇开头字面相似度 ≥0.30（软）。
2. **论证顺序去重**：≥3 场里 60% 以上按同一顺序（如「排名 → 主客 → 近况」）排 → 流水线（硬）；多场小节首句同一开头（如每场都「结论：」）（软）。
3. **段落节奏去重**：段落长度变异系数 <0.30 → 整齐得像流水线（软）；句长参差仍按 R57（sd ≥ 8）。
4. **观点表达去重**：「我的判断是 / 站主队 / 站客队 / 防平局 / 说白了 / 问题来了 / 先给结论」等单篇 ≥3 次（软）。
5. **结尾去重**：与上一篇同一收尾方式（软）；**连续第三篇以提问收尾（硬）**。结尾在「总结观点 / 悬念留白 / 观点反问 / 比赛观察点 / 认错条件」间按主题选。

> **去重不是换同义词，而是换信息组织方式。**同样一组数据，今天可以从异常现象开始，下一篇从双方的矛盾开始，再下一篇先提出一个错误认知再纠偏。

## 八、三个特色栏目（共享同一套 AFEI 数据底座）

| 栏目 | 风格组合 | 定位 |
|:--|:--|:--|
| 《阿飞看球》 | A 老球迷观察 | 轻松讲比赛、聊球队，强化人物个性 |
| 《阿飞拆局》 | B 数据分析 + D 战术对抗 | 用数据和比赛机制解释胜负条件，强化专业辨识度 |
| 《阿飞复盘》 | E 反常识纠偏 + G 赛后复盘 | 赛前判断与实际赛果对照，讲清对在哪、错在哪 |

## 九、与现有铁律的兼容改写（本仓库特有，用户方案未覆盖处）

1. **R53 退役**：旧池「S02 老球迷吐槽 / S05 倒叙复盘 / S07 战术棋局 / S10 误区粉碎」这类条目其实是风格，不是结构，已分别归入新风格 A / G / D / E；新结构池只管叙事顺序。旧命令 `pick_structure.py` 保留为转发壳。
2. **R32 篇幅双档**：常规文章（A–G）照走 800–1500 字；**H 型极简快评（微头条/短图文）单独走 300–500 字档**（2026-11-07 用户拍板，`wordcount.py / preflight.py` 支持 `--short` 或文件名含 `_快评`）。
3. **R55 内外分层**：G 的「哪个参数该修正」只进内部校验文件；D/E 的数据论证同样不出现内部术语。
4. **R56 必备要素**：任何风格与结构都必须每场有具体数据 + 明确立场 + `推荐比分：X 比 Y（首选）／…（次选）／…（防范）`（不站方向也要写明「不站」）。C 型悬念不能把这些藏起来。
5. **R58 防同质化**：头条把「多篇套同一故事框架换队名」判 -70 分档，本引擎就是防这个的工程措施；同批多篇必须风格或结构至少一层不同。
6. **R60/R61 证据强度**：风格不改变「能说多满」——弱证据场次在任何风格下都只能写「弱倾向 / 观察」；E 型的「纠偏」也不许用 <5pp 的分歧写成「严重低估」。
7. **人设第零层**：所有风格都是「阿飞」在说话——懂数据的老球迷、敢讲不同意见、不装神。风格换的是讲法，不是换人。

## 十、文章质量标准

有数据，不堆数据。有观点，不先定结论再找证据。有专业度，不写成模型报告。有幽默，不刻意制造段子。有悬念，不隐瞒关键信息。有判断，也有反向验证。预测错了必须允许复盘。

## 十一、最终目标

让不同文章在表达方式、叙事节奏、信息排列和观点呈现上有差异，同时保持稳定的人物身份——**阿飞·赛博聊球**。

**数据不会说谎，但人会。不是荐彩大神，而是帮读者把比赛看明白的人。**

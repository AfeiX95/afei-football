# 📕 小红书图文卡片（每场三张 3:4 图）

> 一句话：**双击仓库根的 `小红书出图.cmd`** → 按 `1` 出最新一批 → 图在 `📝文章/<日期>/小红书/`，文案在同目录 `文案.md`。
> 出图 = **HTML + 本机 Chrome headless 截图**（`scripts/xhs_html.py`，不联网、不装任何依赖、不需要 Key、不生成 docx/PDF）；装了 playwright 的话可用 `--engine playwright` 换成**版本固定、快一倍**的内置 chromium。
> 定版风格：**杂志风 editorial**（米白纸底＋衬线大标题＋细分隔线）。另备一版「瑞士风 swiss」（白底＋粗黑线＋橙色强调块），菜单里按 `2` 可两版同出对比。

## 为什么单做一套

头条/公众号是长文，小红书是**图文**：一屏一个信息块、3:4 竖版。所以「矩阵」＝把一次在售档里挑出的场次
**每场渲三张卡**（判断卡 / 战绩卡 / 深读卡，共 10 张含封面），配一段可直接粘贴的正文。同一批数据、两种媒介，不用重写内容。

## 每场三张卡（2026-10-12 用户定的内容清单）

用户原话：**「卡片图片每期还是多样化。但其中要包含核心矛盾，本次看点，战意，信号。加上两队近期战绩对比。再贴一个六维雷达对比图」**。落法是**拆卡**，不是往一张里硬塞：

| 卡 | 装什么 | 回答的问题 |
|:--|:--|:--|
| **判断卡** | 我的判断（立场）· **核心矛盾** · 三向概率（我/机构）· 高概率比分三档 | 我站哪边、为什么 |
| **战绩卡** | **近期战绩对比**（近 5 场胜平负 pills + 主客 10 场 + 场均进失 + 交锋）· **本次看点**（2 条，带 01/02 编号块） | 两队现在什么状态、这场看什么 |
| **深读卡** | **六维雷达对比** · 战意 · 信号 | 六个维度谁强谁弱、依据是什么 |

- **多样化**靠 `variant`（同一批里偶数场把块序对调：判断卡＝概率↔比分，战绩卡＝战绩↔看点，深读卡＝雷达↔战意/信号），
  所以三场不会是同一张脸；每期的场次、文案、雷达形状本来也不同。
- 六维口径沿用文章那套：**近期状态 / 进攻火力 / 防守稳固 / 主客战力 / 市场支持 / 模型预测**（数据里有交锋时补第七轴「交锋历史」）。

## 傻瓜操作

| 想做什么 | 怎么做 |
|:--|:--|
| 出正式图（定版 editorial） | 双击 `小红书出图.cmd` → 按 `1`（一批）→ 图直接落到那批的 `小红书/` 目录 |
| 换风格 / 两版对比 | 双击 → 按 `1`（选批）→ 按 `2`（editorial + swiss 各出一份到同级 `试版/`） |

命令行等价：

```bash
python scripts/xhs_html.py --menu                     # 同样的交互菜单
python scripts/xhs_data.py --input "📝文章/20261014/小红书/cards.json"          # 先按本地缓存回填 radar / form
python scripts/xhs_html.py --input "📝文章/20261014/小红书/cards.json"          # 默认 editorial，出在同目录（每场三张）
python scripts/xhs_html.py --input "..." --style swiss --out "state/xhs_auto"     # 指定风格与输出目录
python scripts/xhs_html.py --input "..." --style both                             # 两版同出（→ 同级 试版/<style>/）
python scripts/xhs_html.py --input "..." --kind judge                             # 只出判断卡（full 默认三张；还有 form/read）
python scripts/xhs_html.py --input "..." --html-out state/_tmp_tools/html        # 另存中间 HTML（排版诊断）
```

> 兜底：本机若没有 Chrome/Edge，可退回旧版 Pillow 渲染 `python scripts/xhs_cards.py --input "..."`（需 `pip install pillow`，版式是深色卡片风，已不再作为定版）。

## 截图引擎（三选一）

`--engine chrome | playwright | auto`（**默认 `chrome`**，与已发布成品逐像素一致）：

| 引擎 | 依赖 | 4 张实测 | 特点 |
|:--|:--|:--|:--|
| `chrome`（默认） | 本机 Chrome / Edge | ~3.5s（0.9s/张） | 零依赖；但跟着本机 Chrome 版本走，换机器像素会变 |
| `playwright` | `pip install playwright` + 内置 chromium（一次性约 310MB） | ~2.3s（0.4s/张） | 浏览器复用、快一倍、**版本固定**（跨机一致）；`--engine auto` 有就自动用 |
| 旧 Pillow 版 | `pip install pillow` | — | 深色卡片风，仅作没浏览器时的兜底 |

- 三条路径**版面完全一致**（墨带条数逐条对齐，位移 ≤ 9px / 0.3%），差别只在字形抗锯齿：本机 Chrome 154 与 playwright 内置 chromium 153 的栅格化不同（3–7% 像素、最大通道差 ≤233）。
- 本机 `puppeteer` 25（自带 Chrome 155）也验过：出图正常，但比 playwright 慢一倍且无额外好处，故**未接入**。

```bash
python scripts/xhs_html.py --input "..." --engine playwright      # 版本固定 / 快一倍
```

## 输入文件（`cards.json`）字段

agent（或你自己）在 `📝文章/<日期>/小红书/cards.json` 写一批，脚本据此出图：

| 字段 | 作用 |
|:--|:--|
| `title` | 封面大标题（也是正文首句） |
| `xhs_title` | **小红书标题（≤20 字，平台硬限制）**，只在 `文案.md` 里提示 |
| `subtitle` | 封面副标题 |
| `cover_kicker` / `cover_items` / `cover_hint` / `cover_tail` | 封面小标、三条要点、下半段提示、底部读图说明（都可省，有默认值） |
| `tags` / `brand` / `source` | 话题标签（≤3，见写作铁律）、品牌、数据来源 |
| `matches[]` | 每场三张卡：`no` `league` `kick` `home` `away` `stance` `probs_mine` `probs_mkt` `score[首选,次选,防范]` `contradiction` `focus[两条]` `will` `signal` `note` |
| `matches[].sporttery_match_id` | 竞彩场次 id（如 `2041959`）。填了才读得到本地缓存 `state/_match_<id>/`，用来算雷达与战绩 |
| `matches[].form` / `matches[].radar` | **不用手写**，`python scripts/xhs_data.py --input <cards.json>` 会从本地缓存算好回填（`--dry` 只打印、`--force` 重算） |

- `probs_mine` / `probs_mkt` 都是 `[主胜, 平, 客胜]` 的百分数；只想放一边就省掉 `probs_mkt`。
- `score` 三档顺序固定为**首选 / 次选 / 防范**（与文章 R30 一致）。
- `contradiction` 一句话讲清本场**核心矛盾**（机构怎么看 vs 数据怎么看）；`focus` 是 1–2 条**本次看点**，每条 ≤ 28 字最稳。
- 缺字段会自动留白（例如 `--auto` 市场版没有 `stance`/`will`/`signal`，就不画那几块）。
- ⚠️ 交锋历史：本地缓存里 `history` 的 `teamId` 与 `result` 的 `teamId` **不是同一套**，`xhs_data.py` 按**队名**匹配；
  匹配不到（例如 10-14 三场欧冠）就自动把第七轴去掉、`h2h` 为空，不硬编。

## 出图前会先过一遍词表

渲染前用 `📚知识库/模型脚本/check_article.py` 的 `HARD_BANNED` / `SOFT_BANNED` 逐字段查
（赔率·盘口·庄家·打穿·北京时间·今天·明天·今晚·投注·水位…）。命中就**拒绝出图**并打印是哪个字段哪个词，
所以图上不可能出现违规表述。

- 写 `stance`/`will`/`signal` 时按 **R41 替写表**：让球 → 门槛 / 一球的差距；受让 → 站住 / 不输球；赔率 → 定价。
- **时间只写绝对日期**（`10/14 00:45`），不写「今晚/明天/北京时间」。

## 版式

- 画布 **1080 × 1440（3:4）**，导出 **2 倍图（2160×2880）**，截图命令等价于
  `chrome --headless=new --hide-scrollbars --force-device-scale-factor=2 --window-size=1080,1440 --screenshot=...`（约 1 秒/张）。
- **editorial（定版）**：米白纸底 `#f3f0e8` + 墨黑 `#0a0a0b` + 赭石强调 `#9b5a2e`；衬线大标题（对阵）、标题下细分隔线、
  **我的判断**（赭石大字）、核心矛盾（左侧粗黑条）、三向概率（我＝黑实条 / 机构＝灰条，两行对照）、高概率比分三栏、
  战绩两行 pills（胜＝黑 / 平＝灰 / 负＝赭石）、看点两条白底编号块、六维雷达（我＝赭石实线、对手＝蓝实线）、战意/信号带分隔线。
- **swiss（备选）**：纯白底 + 纯黑 8px 粗线 + 橙色 `#e8402a`；黑/橙 chip 顶栏、核心矛盾反白黑块、首选比分整块刷橙、
  看点橙框块、雷达我＝橙线 / 对手＝黑线、战意/信号用黑橙标签块。
- 衬线字体用技能自带资源 `C:\Users\wuyan\.agents\skills\claude-design-card\assets\NotoSerifSC-Regular.ttf`
  （复制到临时目录后 `@font-face` 内嵌）——本机没装思源宋体，但这样不依赖安装。
- 正文用系统 `Microsoft YaHei UI`；图标一律用**色块/方块**，不用 emoji（中文字体里 emoji 变豆腐块）。

## 渲染踩过的坑（改版式前先看）

1. **卡片是 `display:flex;flex-direction:column` 的固定高容器**：任何「固定高度的小装饰条」（分隔线、粗黑条）
   都会被 flex 压缩成 0 高度，画面上直接消失。必须写 `flex:none`。
2. 内容偶尔写长了会把页脚顶出画布：`xhs_html.py` 里有 JS 兜底（放不下时整张卡等比缩，最多 6%）；
   出图后还会量**底部留白**，`< 24px@2x` 就打印 `⚠️` 提醒去 `cards.json` 精简文案。
3. `.cmd` 一律**只写 ASCII**：中文注释 + LF 会让 cmd.exe 误切行，报 `'hon"' is not recognized` 这种莫名其妙的错。
4. `load_input()` 返回的是 `(data, cards)` 元组，别当 dict 用；`subprocess` 读 Chrome 输出**不要用 `text=True`**
   （stderr 里有非 GBK 字节会 `UnicodeDecodeError`），要自己 `decode("utf-8","ignore")`。
5. **别把内容硬塞进一张卡**：判断卡＋核心矛盾＋概率＋比分＋战绩挤在一张 ≈1620px（上限 1440），会顶掉页脚。
   判定方法：`--html-out <目录>` 存下中间 HTML，再用 `python state/_tmp_tools/measure.py <目录>` 量每张的真实内容高度
   （它会把 `#fit` 的自动缩放复位到 1，报「内容底 Npx / 余或超出多少」）。**拆卡比压字号好看**。
6. 雷达图两条线都要**实线**（早先用虚线区分对手，读者会误以为「不确定」）：靠颜色 + 线粗区分即可。

## 发布流程

1. 双击 `小红书出图.cmd` → `1`，拿到 `01_封面.png` + 每场三张（判断/战绩/深读）+ `文案.md`。
2. 打开 `文案.md`：按 `【标题】` 填小红书标题（**≤20 字**，超了平台会截）→ `【正文】` 直接粘贴 → 末尾标签。
3. 发布时间按 **R39**：主档 **10:30–13:00**，避开 16:00–19:00。
4. 图片顺序：封面 → 周二004 判断/战绩/深读 → 010 三张 → 011 三张（文件名序号即顺序）。三场＝10 张，小红书单篇上限 18 张；
   场次多到超过 18 张时，用 `--kind judge` 只出判断卡，或拆成两篇。

## 和文章的关系

- 内容同源：立场 / 三向概率 / 比分三档 / 战意 / 信号都来自内部全维度分析（**R43**：从全维度分析抽角度写公开稿）。
- 图上只留**结论与依据各一句**，长论证留在文章里；想让人读长文，就在正文末尾带一句引导。
- 一次在售档同时产出：文章（`📝文章/<日期>/*.md`）+ 卡片（`📝文章/<日期>/小红书/`）。

## 已知限制

1. 没有外媒源（R33 只要求长文；图上放不下，省）。
2. 市场版（`xhs_cards.py --auto`）只有机构概率，没有立场，适合铺量或当写稿底稿；HTML 版暂只吃 `cards.json`。
3. 图里不写具体两位小数定价（门禁口径也不鼓励），要报价看盘口库或文章附表。
4. 历史批次只有本机（与 `state/odds.sqlite` 一样不进 git 的只有盘口库；`cards.json` 和 PNG 是跟 git 走的）。
5. 出图依赖本机 Chrome/Edge（`--engine chrome`）；想固定浏览器版本、跨机器像素一致，就 `pip install playwright` 后用 `--engine playwright`（或 `auto`）；两个都没有再退回 Pillow 版。
6. 雷达 / 战绩**只能来自本机竞彩缓存** `state/_match_<sportteryMatchId>/`（脚本取快照、不联网）：缓存过期或没抓过这场，
   就填 `sporttery_match_id` 后跑一次 `python scripts/sporttery_fetch.py match <id>` 再 `xhs_data.py --input ...`。
   Pillow 兜底版**不画**核心矛盾/看点/战绩/雷达（HTML 版专有）。

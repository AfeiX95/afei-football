## 为什么单做一套

头条/公众号是长文，小红书是**图文**：一屏一个信息块、3:4 竖版。所以「矩阵」＝把一次在售档里挑出的场次
**每场渲一张全信息卡**（含封面，三场＝4 张），配一段可直接粘贴的正文。同一批数据、两种媒介，不用重写内容。

## 🤖 后台模型块：胜率 + 比分概率（2026-10-13 加，并进单卡）

| 卡上的块 | 长什么样 | 数据来源 |
|:--|:--|:--|
| **胜率条** | 左＝主队、右＝客队，中间一条**粗点线**（主胜/平的分界），三档都带百分比 | `model.wdl` = [主胜, 平, 客胜] |
| **比分概率热力图** | 格数**按 λ 自适应**（λ≤2.6 画 5×5，否则 6×6），**颜色越深概率越高**，格内写百分数，最高格加粗框 | `model.grid` |

| 抽样复核 | 胜率条右上「抽样 2 万 次，差 0.4 个百分点」 | `model.mc_delta` / `n_mc` |
| 简报 | 底部（A/B 模板在四格行上方，C 模板之后） | `brief` |

## 🎨 卡片风格（每期轮换：米白 / 瑞色 / 瑞士）

2026-10-13 用户要求：「卡片风格轮换为瑞色风或者其他」——**风格和模板是两个维度**：模板换块序，风格换配色/字体/封面。

| 风格 | cluster | 长相 | 一句话 |
|:--|:--|:--|:--|
| `editorial`（默认） | `.ed` | 米白底 + 赭石 #9b5a2e + 衬线大字 | 杂志感，最稳 |
| `rouge`（**瑞色**） | `.rg` | 粉调暖底 + 朱砂 #b8322a + 衬线大字 | 用户口中的「瑞色风」＝暖红/朱砂 |
| `swiss` | `.sw` | 纯白 + 黑 + 正红 #e8402a + 无衬线 | 瑞士风（早期做的，若显示不对先别用） |

- 轮换账本 `state/xhs_styles.json`（`{批次目录名: 风格, "_last": 风格}`），规则和模板一样：**同一批重出不跳、换一批必换**；优先级 `--style xxx` > `cards.json` 的 `"style"` > 账本轮换。
- `--style auto`（默认）走轮换；`--style both` 是老用法（editorial + swiss 各出一遍），**不再用于小红书**。
- `📝文章/20261014/小红书_第一批/` = rouge + 模板 B；`小红书_第二批/` = editorial + 模板 A；`小红书_第三批/` = rouge + 模板 C（2 场）；`小红书_第四批/` = swiss + 模板 B（1 场）；`小红书_第五批/` = editorial + 模板 A（3 场）——同一天五批，风格与模板两两错开。

### ⚠️ 换风格必踩的坑：扩展 CSS 的 `.ed` 前缀

`EXTRA_CSS` / `ALL_CSS` / `DATA_CSS`（战绩行、简报、四格、模型行……整块版式）本来都是照 editorial 的 `.ed` 写的。
换到 `.rg`/`.sw` 时**必须把前缀换成当前 cluster**，否则整块版式静默失效：瑞色风第一次渲染就出现过「战绩行变成一坨纯文本、简报跑到战绩前面、字号全乱」——`ext_css(cluster)` 就是干这个的（`scripts/xhs_html.py`，四处 `<style>` 都走它）。新增扩展 CSS 一律**用 `.ed` 前缀写**，别写死 `rg`。

**第二个坑（瑞士风，2026-10-13 修）**：`.ed .cq p{color:#141310}` 被 `ext_css` 换成 `.sw .cq p{…}` 后，**深色正文会被压到黑底上**（`.sw .cq{background:#000;color:#fff}` 的 `color` 是父级继承，输给直指 `p` 的规则），图上「数据反差」整块看不见字。
修法：在 `DATA_CSS` 末尾补一条同优先级的反向规则——`.sw .cq p{color:#f4f4f2}`（`DATA_CSS` 在级联最后，靠**顺序**胜出）。**换风格后必须逐块目测一遍**：正文、标签、页脚三处的「深底浅字 / 浅底深字」都可能被前缀替换带偏。

## 一张卡装什么（⚠️ 旧「全信息单卡」形态，仅作代码参考：`--kind all`）

用户原话：**「卡片图片每期还是多样化。但其中要包含核心矛盾，本次看点，战意，信号。加上两队近期战绩对比。再贴一个六维雷达对比图」**
（后又补：**「六维度含：进攻能力/中场控制力/防守能力，另外每场只要集中在一张卡片体现所有分析信息」**）。

| 你要的项 | 卡上的块 | 说明 |
|:--|:--|:--|
| 我的判断（立场） | 「我的判断 + 一句话」 | 与标题同一行，赭石大字 |
| **核心矛盾** | 左侧粗黑条块 | 机构怎么看 vs 数据怎么看，1–2 行 |
| 三向概率 | 主胜/平/客胜三栏 | 我＝黑实条，机构＝灰条（并排对照） |
| 高概率比分 | 首选/次选/防范 | 与概率并排，省一半高度 |
| **两队近期战绩对比** | 两行 pills | 近 5 场胜平负串 + 主客 10 场 + 场均进失 + 交锋（有则写） |
| **六维雷达对比** | 内联 SVG | 我＝赭石粗实线、对手＝蓝实线，逐轴标两个数 |
| **本次看点** | 01/02 编号块 | 两条并排（两列），省一半高度 |
| **战意 / 信号** | 带分隔线的两段 | 与雷达并排，填满右侧空档 |

- **多样化**靠 `variant`：同一批里偶数场把**左右列对调**（概率↔比分）并把**看点整块提到雷达行之前**，
  所以三场不会是同一张脸；每期的场次、文案、雷达形状本来也不同。
- 六维口径（2026-10-12 用户指定前三轴）：
  **进攻能力** = 近 10 场场均进球 ÷ 3 × 100 ；
  **中场控制力** = 50 + 近 5 场场均净胜球 × 14 + (不败率 − 0.5) × 20（**控场代理**，本地缓存没有控球率/传球数据）；
  **防守能力** = (1 − 场均失球 ÷ 3) × 100 ；
  **近期状态** = 近 5 场积分率（`recent_rate()`） ；
  **进球稳定性** = 0.5 ×（近 5 场有进球场次占比）+ 0.5 ×（100 − 进球数标准差 × 30）（`stable_rate()`）；
  **主客战力** = 同主客 10 场胜率（有 ≥3 场交锋数据时该轴换成 **交锋历史** = 该队交锋胜率）＝ 六轴全部由公开赛果算出，不含市场支持。

## 输入文件（`cards.json`）字段

agent（或你自己）在 `📝文章/<日期>/小红书/cards.json` 写一批，脚本据此出图：

| 字段 | 作用 |
|:--|:--|
| `title` | 封面大标题（也是正文首句） |
| `xhs_title` | **小红书标题（≤20 字，平台硬限制）**，只在 `文案.md` 里提示 |
| `subtitle` | 封面副标题 |
| `cover_kicker` / `cover_items` / `cover_hint` / `cover_tail` | 封面小标、三条要点、下半段提示、底部读图说明（都可省，有默认值） |
| `cover_label` / `cover_date` | 封面左上角色块文字（默认「**今日赛事前瞻**」）与日期行（如「2026.10.14 周二」；不写就退回 `cover_kicker`） |
| `style` | 可选，`"editorial"`/`"rouge"`/`"swiss"` 指定本期风格；不写就按 `state/xhs_styles.json` 轮换 |
| `tags` / `brand` / `source` | 话题标签（≤3，见写作铁律）、品牌、数据来源 |

| `matches[].sporttery_match_id` | 竞彩场次 id（如 `2041959`）。填了才读得到本地缓存 `state/_match_<id>/`，用来算雷达与战绩 |
| `matches[].form` / `matches[].radar` | **不用手写**，`python scripts/xhs_data.py --input <cards.json>` 会从本地缓存算好回填（`--dry` 只打印、`--force` 重算） |
| `matches[].brief` | 100–200 字简报，同上自动生成；**手写覆盖也认**（写了 `brief` 就不再覆盖，除非 `--force`）。历史比分必须写「X 比 Y」，写 `0:1` 会被门禁拦 |
| `matches[].model` | `{lam:[λ主,λ客], grid:6×6 概率, wdl:[主胜,平,客胜], top:[[比分,概率]×3], n_mc, mc_delta}`，由 `python scripts/xhs_model.py --input <cards.json>` 写入；**没有这块就退化成「雷达｜战意要点」**（照样出图） |
| `matches[].lam_override` | `[λ主, λ客]`。写它就**跳过卡片自带的 λ 推导**，直接用给定值算 `model`（`scripts/xhs_model.py` 读）。用途：让**卡片数字与正文/文章完全一致**——`scripts/model.py`（文章口径，含 H2H 修正）与卡片 λ 口径不同，同一场会出现两套百分比。周三三批就是这么注入的（`state/_tmp_tools/inject_lam.py`，行内 2 小时文件，用完删）。**改了 `lam_override` 一定要重跑 `xhs_model.py --force`**，否则 `model` 还是旧 λ 算的 |
| `template` | 可选，`"A"`/`"B"`/`"C"` 指定本期版式；不写就按 `state/xhs_templates.json` 轮换 |

- `probs_mine` / `probs_mkt` 都是 `[主胜, 平, 客胜]` 的百分数；只想放一边就省掉 `probs_mkt`。
- `score` 三档顺序固定为**首选 / 次选 / 防范**（与文章 R30 一致）。
- `contradiction` 一句话讲清本场**核心矛盾**（机构怎么看 vs 数据怎么看），单卡里**控制在 2 行内**（约 ≤ 55 字）；
  `focus` 是 1–2 条**本次看点**，每条 ≤ 30 字最稳（单卡两列并排，长了会把页脚顶出去）。
- 缺字段会自动留白（例如 `--auto` 市场版没有 `stance`/`will`/`signal`，就不画那几块）。
- ⚠️ 交锋历史：本地缓存里 `history` 的 `teamId` 与 `result` 的 `teamId` **不是同一套**，`xhs_data.py` 按**队名**匹配；
  匹配不到或样本 < 3 场（例如 10-14 的 010）就自动把该轴换成**主客战力**，`h2h` 为空，不硬编。
- ⚠️ `source` 不许出现「中国体育 / 竞彩」字样（旧稿写的是「数据来源：中国体育·竞彩」，门禁按「市场折算」拦下）——统一写「数据来源：公开赛事数据」。

## 渲染踩过的坑（改版式前先看）

1. **卡片是 `display:flex;flex-direction:column` 的固定高容器**：任何「固定高度的小装饰条」（分隔线、粗黑条）
   都会被 flex 压缩成 0 高度，画面上直接消失。必须写 `flex:none`。
2. 内容偶尔写长了会把页脚顶出画布：`xhs_html.py` 里有 JS 兜底（放不下时整张卡等比缩，最多 6%）；
   出图后还会量**底部留白**，`< 24px@2x` 就打印 `⚠️` 提醒去 `cards.json` 精简文案。
3. `.cmd` 一律**只写 ASCII**：中文注释 + LF 会让 cmd.exe 误切行，报 `'hon"' is not recognized` 这种莫名其妙的错。
4. `load_input()` 返回的是 `(data, cards)` 元组，别当 dict 用；`subprocess` 读 Chrome 输出**不要用 `text=True`**
   （stderr 里有非 GBK 字节会 `UnicodeDecodeError`），要自己 `decode("utf-8","ignore")`。
5. 改动内容块**必须先量高度**：`--html-out <目录>` 存下中间 HTML，再用
   `python scripts/xhs_measure.py <目录>` 量每张的真实内容高度（它会把 `#fit` 的自动缩放复位到 1，
   报「内容底 Npx / 余或超出多少」，并逐块列高）。单卡是靠**两栏挤压**（概率|比分、雷达|战意信号、看点两列）
   把内容压进 1440 的，硬塞单列会溢出 100px 以上。
6. 雷达图两条线都要**实线**（早先用虚线区分对手，读者会误以为「不确定」）：靠颜色 + 线粗区分即可。
7. 雷达的六轴标签是横向最长的元素（「中场控制力」5 个字）：SVG 宽度要留 `size + 300`，
   否则右轴的标签会顶出画布；单卡里雷达宽度只有 500，**图例必须挪到图下方横排**，挤在右边会把队名折断。
8. 旧批次的 PNG 不会自动清理：重出前先删同目录旧 `*.png`，否则三卡版和单卡版会混在一个文件夹里。

### 数据向改造后新踩的坑（2026-10-12）
- **历史比分要写「X 比 Y」**：门禁的「比分串」规则只拦 `\d[-:]\d`（博彩比分串的形状），`3 比 0` 放行。
- `feature.json` 的平局键是 **`homeDrawMatchCnt` / `awayDrawMatchCnt`**（没有 `Goal` 后缀）；写成 `homeDrawGoalMatchCnt` 会静默取到 0，
  简报里就会出现「7胜0平1负」这种胜平负加起来不等于 10 的假数据。
- 简报别写战术风格（边路 / 直塞 / 阵地战）：本地竞彩缓存里没有控球、传球、射门这类数据，写了就是编。
- 战意 / 数据要点也只写赛果：旧稿里「两队本季都把主力轮换放在联赛」这类推测句已删（无源＝编，且容易被读成暗示）。

- 队名 4 个字（国际米兰 / 比利亚雷 / 埃因霍温）在战绩行会折行 → `DATA_CSS` 把 `.card.data .frow .tn` 定成 `flex:0 0 152px`。
- 右侧段落标题「数据要点」也会折行（`nl` 宽度扣掉图标后不够 4 个字）→ `.card.data .note .nl` 定成 `flex:0 0 118px`。

- 门禁要**连正文一起扫**（`scan_text(cap, "文案正文")`）：只扫 `cards.json` 字段的话，正文里写「我猜 2-1」就能绕过卡片层的检查。
- 文案正文里的历史比分要写「X 比 Y」（如「主场 3 比 0」）才过门禁；`0:1` / `2-1` 会被「比分串」规则拦下。**预测比分别写**（2026-10-13 二审后已从正文撤掉）。
- `caption_text()` 的 data 分支用 `re.S` 整块抓 `【正文】` 时，要**截到标签行之前**，否则正文会把 `#标签` 一起吞进去（正文字数就虚高）。

### 并成一张卡时踩的坑（2026-10-13 晚，用户定「只出一张卡」）

   **不写比分、不写胜率/概率、不提模型推演**；全部由 `caption_text()` 生成，出图时已被门禁（含 `scan_caption()`）扫过；**卡片的说明行别删**（读者靠它知道要往右划）。
   - ⚠️ `文案.md` 以前只在 `--style editorial` 时写，2026-10-13 改成**任何风格都写**（换风格后不再丢了）。
3. 发布时间按 **R39**：主档 **10:30–13:00**，避开 16:00–19:00。
4. 图片顺序：封面 → 场次文件名序号即顺序。三场＝4 张，小红书单篇上限 18 张，
   也就是说一次可以放到 **17 场**；场次更多时拆成两篇。
5. 同一天可以出**多批**（`小红书_第一批/`、`小红书_第二批/`……），每批 4 张、各自一套风格+版式，互不干扰。

## 和文章的关系

- 内容同源：立场 / 三向概率 / 比分三档 / 战意 / 信号都来自内部全维度分析（**R43**：从全维度分析抽角度写公开稿）。
- 图上只留**结论与依据各一句**，长论证留在文章里；想让人读长文，就在正文末尾带一句引导。

## 已知限制

1. 没有外媒源（R33 只要求长文；图上放不下，省）。
2. 市场版（`xhs_cards.py --auto`）只有机构概率，没有立场，适合铺量或当写稿底稿；HTML 版暂只吃 `cards.json`。
3. 图里不写具体两位小数定价（门禁口径也不鼓励），要报价看盘口库或文章附表。
4. 历史批次只有本机（与 `state/odds.sqlite` 一样不进 git 的只有盘口库；`cards.json` 和 PNG 是跟 git 走的）。
5. 出图依赖本机 Chrome/Edge（`--engine chrome`）；想固定浏览器版本、跨机器像素一致，就 `pip install playwright` 后用 `--engine playwright`（或 `auto`）；两个都没有再退回 Pillow 版（不画矛盾/看点/战绩/雷达）。
6. 雷达 / 战绩**只能来自本机竞彩缓存** `state/_match_<sportteryMatchId>/`（脚本取快照、不联网）：缓存过期或没抓过这场，
   就填 `sporttery_match_id` 后跑一次 `python scripts/sporttery_fetch.py match <id>` 再 `xhs_data.py --input ...`。
7. **中场控制力是代理指标**：本地缓存只有比分与胜平负，没有控球率/传球/射门数据，所以这一轴由「场均净胜球 + 不败率」折算，
   口径写在 `scripts/xhs_data.py` 的 `control_rate()`；以后若接入含场面数据的数据源，替换这一个函数即可。
8. 单卡密度高＝**文案必须短**：`contradiction` ≤2 行、每条 `focus` ≤30 字、`will`/`signal` 各 ≤2 行；超了就会触发第 2 条的 `⚠️`。
9. **模型块的口径不含市场**：λ 只由同主客场均进/失球算出，所以胜率与「机构三向」不是一回事；要报定价得另取盘口库，图上也**不出现**机构/定价字样。
10. 概率与比分是**后台模型算的分布**（不是赛果、不是推荐）。2026-10-13 实测：**图上可以发**，但**正文绝不能出现比分猜测与概率/胜率数字**（`xhs_riskcheck.scan_caption()` 会拦）；首个通过版本＝`📝文章/20261014/小红书_第二批/`（4 张 + 306 字正文）。

# 外部预测源实测（第三方参照层）

> 目的：把「外部预测 / 后台模型 / 市场折算」摆成三方对照。外部预测**只作参照，不改模型结论**。
> 首建 2026-10-17（用户贴《全球 10 大 AI/算法足球比分预测平台》报告后要求「接搭建落地」，当天统一实测）。
> 脚本：`scripts/ext_predict.py`；管线位置见 `docs/WORKFLOW.md` §3B。

## 一、平台实测结论（2026-10-17）

| 平台 | 判定 | 实测依据 | 能否接进管线 |
|:--|:--|:--|:--|
| **Sports Mole** | ✅ 可用 | 静态 HTML，`/preview/…-prediction-team-news-lineups_<id>.html` 页内含**预测比分 + 首发 + 赛前判断长文**；索引页/联赛页/球队页都能顺着 `/preview/` 链接找到 | **已接**（唯一自动源） |
| Forebet | ❌ 挡 | 直连与 Playwright 无头/有头均落到 Cloudflare 挑战页，拿不到概率与波胆 | 否 |
| PredictZ | ❌ 挡 | 同上（Cloudflare） | 否 |
| Windrawwin | ❌ 挡 | 同上 | 否 |
| NerdyTips | ❌ 挡 | 需注册登录才给置信度评分，未登录页无场次数据 | 否 |
| FootyStats | ❌ 挡 | Cloudflare + 高级数据订阅墙，免费层只有聚合页 | 否 |
| AiScore | ❌ 挡 | App 型站点，网页端靠 JS 拉接口，直连拿不到结构化预测 | 否 |
| KickOff / Soccersm / Betaminic | ❌ 挡 | 挑战页或登录墙；Betaminic 偏回测策略库，本身不产出单场比分 | 否 |
| Sofascore | ⚠️ 仅手工 | 有公开 API 但字段随版本变、且无「赛前比分预测」，只有实时势头/评分 | 只作临场人工参考 |

**结论**：这十家里真正能稳定免费拿到「赛前比分 + 首发 + 判断理由」的只有 Sports Mole。其余不是反爬，就是登录墙——**不在反爬上投入时间**。

## 二、Sports Mole 抓取路径（已被脚本封装）

1. **索引页** `https://www.sportsmole.co.uk/football/predictions/`：只收录部分联赛，别指望全覆盖
2. **球队页** `https://www.sportsmole.co.uk/football/<team-slug>/`：列该队近期所有 `/preview/` 链接 —— **索引页漏掉的场次靠这里兜**
3. **预览页** 内含三样东西：`X 2-1 Y` 预测比分（§prediction-title）、双方 predicted lineups、2-6 段赛前判断
4. 中文队名 → slug 的映射在 `database/config/team_aliases.json`（`sm_slug` / `sm_alias`），新队名直接补一行即可

**坑**：①`html.unescape` 必须在灭标签**之前**，否则 `&nbsp;` 会混进比分串（曾出现 `Brentford 2-2 Liverpool &nbsp`）；②英超以外的联赛索引页常年缺行，一律走球队页兜底；③页面摘要里常混着两个队的段落开头（`Bilbao Valencia have struggled…`），引用时只取判断句。

## 三、人工兜底（没有预览页的场次）

```bash
python scripts/ext_predict.py --date 20261017 match 斯特拉斯 巴黎圣曼 --manual \
  --predicted "0-2" --source "Sports Mole 摘要" --note "主队两连败，客队欧冠 4-2 胜曼城后轮换存疑"
```

手动记录会标 `manual`，报告里同样参与「方向是否一致」的判断。**禁止为了凑齐六场而编造外部预测**——搜不到就不写这一列。

## 四、怎么用（写作层口径）

1. **方向不一致的场次优先写**：外部说 A、模型说 B，说明这场存在结构性分歧，正好是「核心战术矛盾点」的素材
2. 引用句式：「公开赛前预报给的是 2-1」「第三方直播站的赛前判断是 0-2」——**中性、不带操作建议**
3. 外部预测与市场同侧时，用来给「市场折算」做独立旁证；与模型同侧时，用来给模型结论加一层外部支撑
4. 🔴 不写「推荐」「跟着买」「稳赢」；不把外部预测当结论，稿子里的结论仍然来自后台模型 + 市场折算的对照

## 五、脚本命令速查

```bash
python scripts/ext_predict.py --date 20261017 index                    # 看索引页收了哪些场次
python scripts/ext_predict.py --date 20261017 match 曼城 伊普斯         # 单场直连
python scripts/ext_predict.py --date 20261017 batch --file fixtures.txt # 批量（每行：主队 客队）
python scripts/ext_predict.py --date 20261017 show                      # 打印本批记录
python scripts/ext_predict.py --date 20261017 report                    # 生成 _外部预测对照.md（含三方表 + 方向不一致清单）
```

- 缓存：`state/_ext_raw/`（原始 HTML，便于复核）
- 本批记录：`state/_ext_<日期>.json`
- 报告产物：`📝文章/<日期>/_外部预测对照.md`（下划线开头，是内部参照件，不进发布清单）

## 六、已知限制

1. 只有 Sports Mole 一家 → 覆盖不全（本轮六场里 5 场直连命中，1 场靠球队页兜）
2. 摘要为英文原文，中文稿引用要自己译；只引判断句，不引赔率/让球数字
3. 预测比分与实际首发强相关，首发变（尤其轮换）时外部预测的比分会失真
4. 报告里的「后台模型」列取自 `state/_model_<日期>*.txt` 的胜平负块；**让球块不参与对照**（解析时已跳过，防覆盖）

## 一、总体架构

```
AFEI Football AI v3.0


Layer 0  比赛上下文识别    Match Context

        ↓

Layer 1  数据采集层        Data Collector

        ↓

Layer 2  比赛分析层        Analysis Engine

        ↓

Layer 3  数学模型层        Model Engine

        ↓

Layer 4  预测决策层        Prediction Fusion Engine

        ↓

Layer 5  内容生成层        Content Generator

        ↓

Layer 6  反馈学习层        Feedback Learning



Database:

matches/        每场比赛JSON记录
models/         模型版本与参数
weights/        动态权重配置快照
cases/          典型案例库（H2H/冷门/异常）
```

### 核心原则

| 原则 | 说明 |
|:-----|:------|
| **Layer 0先行** | 任何分析前先识别比赛上下文类型（联赛/杯赛/德比/资格赛/保级战） |
| **单向数据流** | Layer 0→1→2→3→4→5，禁止逆向 |
| **层间只传JSON** | 每层输出都是结构化数据，非自然语言 |
| **每层只干一件事** | 数据层不分析，分析层不建模，模型层不决策 |
| **内容层不修改预测** | 为文章"好看"而改预测结果 = 系统腐败 |
| **预测融合层独立** | 不把经验规则写死在模型里，保持模型可迭代 |

### Layer 0：比赛上下文识别

在进入任何数据采集之前，先确定比赛类型。同样的数据在不同上下文下意义不同：

| 上下文标签 | 识别依据 | 对权重的影响 |
|:-----------|:---------|:-------------|
| `normal_league` | 联赛常规轮次，无特殊战意 | 使用标准权重 |
| `key_match` | 榜首对话/保级6分战/争冠直接对手 | 心理权重+5% |
| `cup_knockout` | 杯赛单场淘汰赛 | 阵容权重升至25% |
| `derby` | 德比/历史恩怨对决 | 心理权重+15%，主场优势折扣 |
| `qualifier` | 资格赛（数据有限） | 数据可信度系数下调 |
| `friendly` | 友谊赛/热身赛 | **跳过预测** |

## 二、统一比赛数据 JSON Schema（评审修正版）

### 12个一级字段（原9个 → 修正为12个）

```json
{
  "match_context": {},        // Layer 0识别结果：赛事类型/重要性标签
  "team_basic": {},           // 基础排名/积分/身价/年龄/攻防数据
  "performance": {},          // 近5/10场详细战果 + 状态评分
  "tactical": {},             // 阵型/打法/克制关系
  "players": {},              // 核心球员数据/进攻依赖度
  "injury": {},               // 伤停详细（位置/出场占比/影响等级）
  "schedule": {},             // 赛程密度/旅行距离/休息天数
  "environment": {},          // 天气/场地/裁判
  "odds": {},                 // 赔率数值（3+时间点）
  "market": {},               // 市场热度/赔率变化分析/异常检测[独立字段]
  "model": {},                // λ值/MC结果/比分概率
  "prediction": {}            // 最终融合概率/比分推荐/可信度
}
```

**关键修正：** `market`从`odds`中独立出来。赔率≠市场。`odds`存原始数值，`market`存分析结果（热度/异常/效率）。

### 核心字段详解

#### match_context（新增Layer 0）

```json
{
  "match_context": {
    "match_type": "cup_knockout",
    "match_importance": "high",
    "data_confidence": 0.85,
    "market_efficiency": 0.80,
    "home_advantage_modifier": 1.03,
    "weight_profile": "cup"
  }
}
```

#### market（从odds独立）

```json
{
  "market": {
    "overheating": false,
    "overheating_score": 0.12,
    "consensus_level": 0.73,
    "trend_pattern": "monotonic",
    "late_money_direction": "home",
    "odds_model_conflict": false,
    "conflict_gap_pp": 4.2,
    "market_efficiency_score": 0.80
  }
}
```

## 三、动态权重系统（评审修正版）

### 3.1 权重配置表

| 维度 | Normal | KeyMatch | Cup | Derby | Qualifier |
|:-----|:------:|:--------:|:---:|:-----:|:---------:|
| **模型(Model)** | 30% | 25% | 25% | 30% | 25% |
| **基础实力** | 25% | 20% | 20% | 20% | 25% |
| **阵容状态** | 10% | 15% | **25%** | 10% | 10% |
| **战术匹配** | 10% | 10% | 15% | 10% | 10% |
| **心理/动机** | 5% | 10% | 10% | **20%** | 5% |
| **赔率(经市场效率修正)** | 20% | 20% | 5% | 10% | 25% |

### 3.2 情报拆分（杯赛场景）

原方案情报35% → 拆分为：

| 子项 | 权重 | 说明 |
|:-----|:----:|:------|
| 阵容信息（首发/伤停确认） | 15% | 杯赛最大变量，可信度高 |
| 心理/动机 | 10% | 单场定胜负的心理压力 |
| 赛场环境 | 5% | 天气/场地/裁判 |
| 其他新闻 | 5% | 教练采访/更衣室传闻 |

**情报≠新闻。** 阵容信息有据可查，新闻可能只是烟雾弹。

### 3.3 市场效率修正（赔率权重）

赔率基础权重必须乘以市场效率系数，否则资格赛赔率权重虚高：

```
赔率有效权重 = 基础权重 × 市场效率系数

市场效率系数参考：
  五大联赛    0.90
  世界杯      0.85
  欧冠        0.80
  瑞超/挪超  0.75
  资格赛      0.60
  小联赛      0.45
```

**示例：**
- 普通联赛：20% × 0.90 = **18%**
- 资格赛：25% × 0.60 = **15%**
- 自动平衡，不再冲突

### 3.4 数据可信度系数（资格赛处理）

资格赛不降低模型权重，而是增加数据可信度系数：

```
模型输出 = 模型概率
可信度 = 系数（正常0.90，资格赛0.55，数据不足0.30）

最终输出不是"主胜62%"而是：
"模型预测：主胜62%（可信度55%，修正后区间54-58%）"
```

| 场景 | 系数 | 说明 |
|:-----|:----:|:------|
| 有完整特征分析页+赔率 | 0.90 | 正常联赛 |
| 只有赔率+少量数据 | 0.70 | 次级联赛 |
| 资格赛+仅1场H2H | **0.55** | 数据极度有限 |
| 完全无数据 | 0.30 | 跳过 |

## 四、异常检测模块

### 4.1 检测项

| 检测 | 条件 | 触发动作 |
|:-----|:------|:---------|
| 赔率vs模型冲突 | 差异>15pp | 赔率权重-10%，模型+5%，情报+5% |
| 热度过载 | 市场一致性>80% | 赔率权重-15%，数据权重+10% |
| 赔率多次下调 | 同一方向连续3次下调 | 过热修正启动 |
| 赔率vs让球盘不一致 | 胜平负和让球方向矛盾 | 标记为"需人工确认" |

### 4.2 热门指数

```
热门指数 = 市场关注度 - 真实实力差

当热门指数 > 15% → 进入冷门扫描
```

## 五、预测融合引擎（Layer 4）

### 5.1 标准融合

```
最终概率 = W1×P_model + W2×P_data + W3×P_odds_mkt + W4×P_intel
```

权重按赛事类型配置，赔率权重经市场效率修正。

### 5.2 情报修正向量

```
P_intel = [0, 0, 0]
for 每条确认的情报:
  前锋缺阵 → P_home -2%
  大雨 → 大球+3%
  主帅危机 → 主队-1%, 客队+1%
```

## 六、反馈学习模块（Layer 6）

### 6.1 双周期反馈

```
短周期（20场）：规则修正
  检测最近20场的偏差模式
  如果某类偏差连续出现3次 → 自动调整个别规则系数

长周期（100场）：权重调整
  全面评估各维度贡献度
  输出权重优化建议
```

### 6.2 存储位置

**不存Hermes Memory。** 使用文件数据库：

```
├── 📁 database/
│   ├── 📁 matches/        # 每场比赛的完整JSON记录
│   ├── 📁 feedback/       # 赛后反馈记录
│   │   ├── short_term/    # 20场滑动窗口
│   │   └── long_term/     # 100场累计
│   ├── 📁 weights/        # 权重配置快照（每次调整归档）
│   └── 📁 cases/          # 典型案例库
```

Hermes Memory只保留：
- 当前模型版本号
- 核心规则（阈值/系数/边界条件）
- 用户偏好

## 八、迁移路线图

### Phase 1（优先）：Adapter Layer

```
旧系统14维输出 → Adapter → JSON → 新Prediction Engine测试
```

立即获得收益，不破坏现有系统。

### Phase 2：Prediction Fusion Engine

当前最大缺口。先写预测融合层：
- 多源概率融合
- 异常检测
- 动态权重
- Data Confidence修正

### Phase 3：Data Collector

最后写。先确定"需要什么数据"，再决定"怎么采集"。

### Phase 4：Model Engine升级

λ公式从`攻击×防守`升级为加权多因子。

### Phase 5：Feedback Learning

双周期反馈系统接入。

## 九、边界条件

| 情况 | 处理 |
|:-----|:------|
| 友谊赛/热身赛 | Layer 0识别后跳过 |
| 数据严重不足(可信度<0.30) | 标"数据不足"不输出 |
| 无赔率数据 | 模型权重+20%，赔率权重归零 |
| 同一时段多场比赛 | 系统不限制，内容层差异化输出 |

### 输出精度

| 输出项 | 格式 |
|:-------|:-----|
| 胜平负概率 | 整数%（如"主胜55%"） |
| 可信度 | 百分比附加在概率旁 |
| 比分 | Top 3 |
| 比赛走势 | 三剧本（正常/胶着/冷门） |
| 风险提示 | ≤3条，只写针对这场比赛的变量 |

## 十、术语表

| 术语 | 定义 |
|:-----|:------|
| Layer 0 | 比赛上下文识别层，决定权重配置和可信度基准 |
| 数据可信度系数 | 评估数据质量的系数（正常0.90，资格赛0.55） |
| 市场效率系数 | 评估联赛市场定价效率（五大0.90，资格赛0.60） |
| 双周期反馈 | 20场短周期规则修正 + 100场长周期权重调整 |
| 热度过载 | 市场一致性超过80%时的风险状态 |
| 热门指数 | 市场关注度减去真实实力差，>15%触发冷门扫描 |
| Market独立 | `market`字段从`odds`独立，存分析结果而非原始赔率 |
| 融合引擎 | Layer 4核心，多源概率加权合并后输出最终预测 |

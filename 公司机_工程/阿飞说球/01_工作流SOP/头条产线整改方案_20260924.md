# 头条产线整改方案(2026-09-24 定案: 单平台化后)

> 背景: 公众号 09-24 被**永久封禁**(3.29.2 体育荐彩类, 主体资质) → **决策: 头条为主阵地; 微信新号只做非体育内容**。
> 本方案解决"头条能不能长期做、要改什么"的问题。**不是词表补丁, 是产线结构调整。**

## 一、风险面(三条叠加才是真风险)

| 风险 | 依据 | 我们的暴露点 |
|---|---|---|
| **① 荐彩形状** | 平台对"荐股荐彩"的判定口径(用户经验贴引述头条客服: **推荐购买指定的…博彩…吸引他人跟进购买**。⚠️ 非官方条文, 需自行核实) | 头条稿含**方向 + 比分 + 让球判读** —— 形状上最接近"推荐"。目前未判, 靠的是**无购买引导 / 无引流 / 无收费 / 无战绩宣传** |
| **② 模板化 / 低质** | 微信 3.28 套路化模板写作; 头条有同质的"低质内容/同质化"治理与信用分扣分 | 每篇同构: 标题格式 + tags + 信息卡 5 行 + 两张表 + 我的看法 + 门槛追问; 一天可发多篇同形态 |
| **③ AI 生成** | 微信 3.27 非真人自动化创作 + 4.24.2 生成式内容标识; 头条亦有对应治理 | 产线是模型生成 + 人工润色, 人工占比低 |

**判断: 单独任一条都未必致命; "AI 生成 + 模板化 + 高频 + 荐彩形状"四条凑齐, 就是平台治理最典型的目标账号。**

## 二、改什么(按优先级)

### P0 — 立刻(不改就会持续暴露)

1. **收敛"推荐"形状**(⚠️ **2026-09-29 用户改规则: 恢复收口比分**)
   - **现行(09-29 起)**: 「我的看法」**主体仍为市场结构陈述**(不让全文变成推荐口吻), 但**结尾允许一句话收口 = 方向 + 比分预测**, 每篇**最多一处**、**不带奖金**、**不得出现"推荐/建议购买/稳"等语境**。
   - **写法四条**: ①先标**盘口**(让球盘 / 胜平负)—— 让球盘的"守住"≠胜平负的"平或客胜"(坑#50); ②方向**跟市场更重一侧**(§5 铁律), 不另起炉灶; ③比分给 **2–3 档**, 不给单一比分; ④紧跟一句限定("这是我读到的结构")。
   - 依据: 头条口径本就允许比分(`risk_audit.py` 对头条"比分形态 N 处(允许, 但不许带奖金)", 只记录不拦; `AGENTS.md` §3 亦写"比分盘最热一档可写")。原 P0.1 的"取消比分"属**自我加严**, 09-29 用户决定放开。
   - ⚠️ **风险留档(改文档不会消掉它)**: 公众号永封依据是 **3.29.2 主体资质** —— 判的是"体育彩票分析、预测"**这件事本身**, 不是用词; **我们改自己的文档, 不改变平台的判定口径**。头条是否安全仍**未核实**(见本文档 §二 P2.8)。
2. **每篇必带一条增量信息**: 伤停 / 首发 / 场地 / 天气 / 教练表态 / 历史纪录, 至少 1 条**三源交叉**。
   这是对"缺乏增量信息价值"最直接的对策, 也是当前产线**最薄**的一块(现在几乎全是竞彩官方数据)。
3. **不同形态连发**: 同一天最多 1 篇串烧 + 1 篇单场, 两篇骨架不同, 发布间隔 ≥ 3 小时(避开"批量、连续发布"的形态)。

### P1 — 一周内

4. **骨架轮换落到实处**(2026-09-29 扩为 **6 套**, 见 `workflow.md` §零·七): ①单点深挖式 ②结构对照式 ③数据先导式 ④赛程密度式 ⑤人物/教练式 ⑥问答式; **近 5 篇不重复, 同日两篇必须不同骨架**, 台账记进当日工作日志。
   - **一篇一个主张**: 主张 = 标题里的反差点; 不服务主张的段落删掉。
   - ⚠️ **表格口径修正(09-29 实测)**: 头条版闸门**强制要求文章含表格**("无表格: 头条版要求用表格表达核心矛盾与数据对比"), 本文档原写的"表格数量 0–2 张可变"**作废** → 改为 **每篇 1 张, 类型按篇轮换**(盘口对照 / 近10场对照 / 赛程时间线 / 数据卡)。
   - 信息卡 **3–4 行**; 没有数据的行(如"天气: 暂无公开数据")**直接删**(上限 6 行)。
   - 结尾模块不再固定"门槛追问"(原有)。
5. **篇幅与标题去打散**(09-29 收紧; **09-30 增"深度单场稿"档**): 单场稿 **800–1000 中文字**, 串烧稿 **900–1100**, **深度单场稿 1200–1500**(用户点名的重点场次, 走 `workflow.md` §零·七 骨架⑦"全景深挖式": 外媒评价+战术对位+核心矛盾+近期状态); 标题 26–34 字浮动。
   - ⚠️ **数字不是越少越好**(09-29 回炉实测修正): 硬指标是**同一数字全篇最多出现 2 次**(表 + 论点句); 总量按住场次 —— 单场 ≤20 / 双场 ≤35 / 三场 ≤55。
   - ⚠️ **同时要守住两道夹缝**: `risk_scan` **纯数据句占比 ≥30%**(硬下限) 与 串烧 **朱雀 <2.0**(硬上限)。做法是**"瘦数据句"**(每句 2–3 个数字 + 夹口语)与**去重复**, 不是删数据; 详见 `workflow.md` §零·七 ③·五。
6. **提高真人写作占比**: 把项目已有的「人工写作 14 特征」从"参考"改成**逐项自检**;
   保留第一人称判断与犹豫; 不再用"模型先写全文→人工润色"的单一流程, 关键段落(开头/我的看法/收尾)由人先写。

### P2 — 需你决定

7. **AI 辅助是否显著标识**: 生成式内容标识是趋势性要求(微信 4.24.2 已明文, 头条有对应规则)。
   三条路: ①显著标注"AI 辅助创作"; ②不标注但把人工占比提高到"AI 只是工具"的程度; ③两者混合。
   **这条我不替你决定** —— 标注可能影响推荐, 不标有合规风险。请先在创作者中心核实头条的具体要求。
8. **核实头条规则**: 登录**头条创作者中心 → 规则中心 / 信用分细则**, 搜「彩票」「荐彩」「赌博」。
   有明文就按明文调整; 没明文就按"**不出现推荐购买语境**"的保守口径执行(见 P0.1)。

## 三、不改什么(这些是资产, 与平台风险无关)

- **数据与校准**: 赛果库 / 校准系数 / 偏差分析 / 复盘 —— 照常, 属私有工具, 不上平台。
- **选场与结构判读**: `slate.py` / `form.py` / `jingcai_fetch.py` 照常。
- **四道闸门**: 继续当**形态检查**, 但**不再当"发布许可"**(坑#55: 闸门只证形态合规, 不证业务合规)。

## 四、明确不做

- ❌ 不用同一身份换号发同类内容(3.13.1 / 3.13.4 属"升级条款": 关联账号可一并永久封号)。
- ❌ 不写"战绩宣传 / 命中率暗示 / 稳赢策略"任何表述(各平台通用硬线, 微信 4.4.2 明列)。
- ❌ 正文不放联系方式 / 引流入口 / 收费渠道。
- ❌ 不用脚本自动发布(平台对"自动化发布"有专门条款; 我们的产线只产出 md, 发布环节保持人工)。

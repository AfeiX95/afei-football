## 3. 出稿铁律(每次必守)
- **数字一律阿拉伯数字**(8场不败 / 2-1 / 0.5球), 不用汉字数字
- 标题: 头条 ≤36字**且必须含「主队vs客队」**, 公众号 ≤60字; 结构 = 具象对立 + 矛盾 + 门槛悬念(禁俗语); SEO = 队名全称 + 赛事 + 钩子; **两版标题必须错开**
- 破折号「——」每篇 **≤6 处**; 超 60 字长句单场 ≤1
- **串烧篇幅(2026-09-12 用户定)**: 头条串烧正文 **1800-2600 全字符**(2026-09-20 校正: 旧写 800-1200 与实做不符), 按**平台全字符口径**量(含标点/数字/标签/信息卡, 不是只数中文字); 结构 = 每场 3-5 句(让球门槛+1 个独有信号+比分), 开篇 ≤3 句, 结尾总述 ≤2 句, **每个数字只说一次**
- **结构差异化是硬要求**: 骨架轮换, 光换开头不算; **多场前瞻时图表位置 / 小节标题 / 结尾方式逐场错开**; 选题倾向热度高场次; 叙事模块【恩怨局】【更衣室热梗】【教练棋局】每篇选 1-3 个、位置错开, 素材必须来自真实数据, 教练/球员对位无可靠来源不点名
- 头条结构 = 倒金字塔; **信息卡 5 行**; 钩子轮换(与近 3 篇不重复); 文末固定【数据来源】+【免责声明】模板; 赛制规则必核查
- **合规红线**: 禁 买/押/下注/赢盘/输盘/收米/稳胆/跟单/必收; 替换 赢盘率→历史成功率、盘路→盘口数据/走势、输盘→走弱; 无比分预测与指向性表述; 免责声明里的"投注"保留
- 发布前用户逐条核查: 概率数字前后自洽、方向逻辑(爆冷=1-0 非 0-1)、教练/转会等事实

## 4. 模型与校准(2026-09-10 重大修正)
- 方向判据 = **市场赔率 + 盘口结构**(主锚); 工具输出的 "Edge校准" 行**只作参考**(理由见下方 45 场实测)
- ⚠️ **旧系数(平局×0.49 / 热门×1.35 / 冷门×0.5)已作废** —— 旧脚本用"让球后结果"配"胜平负赔率"且让球公式符号写反。修正后全量 **469 场 ratio≈1.0 = 竞彩胜平负定价基本有效**, 新系数(2026-09-21 现值) **1.024 / 1.001 / 0.98**(589 场; compute_coefs 已内置 z² 收缩, 见 calibration_state.json), 即 **Edge校准≈裸 Edge**。详见 workflow.md 坑#33
- **铁律: 校准/回测里"结果"与"赔率"必须同盘口** —— 让球后结果只配 hhad 赔率; 赛果 API 不返回 hhad → **让球盘校准做不了**, 不要声称有让球盘系数
- **改公式先手算两例验证**(皇马(-1)2:1→走水、那不勒斯(+1)0:1→走水)
- Edge>30 点需人工泼冷水; **欧战强强 / 跨联赛档位差场景阈值降到 ±15**(λ 盲区)
- ⚠️ **小样本极端防守数据会让模型失效**(2026-09-14 复盘实证两例): 012 赫尔城"客场3场0失球"、029 桑德兰"主场1场0失球" → λ 被算崩, 模型给出与市场完全背离的结论 → **纪律: 某队主/客场样本 ≤3 场时, 模型数字只作参考、不作方向依据, 直接以市场与盘口结构为主锚**
- 让球盘结构(469场): 让球方赢盘仅 **27-32%** / 走水 23% / 受让方不败 **68-77%** → ⚠️ **这是全样本基准, 不是单场方向!**(2026-09-14 复盘: 002/004/029 三场把"受让方不败"当主线写, 结果三场受让方全部没守住, 两场还被客队赢球赢盘) → **正确用法**: 基准只用来判断"市场定价是否异常"; 当市场把让负一侧开得更重时(004 的让负39.9%、029 的39.9%), **以市场那一侧为准**
- ⚠️ **让球盘判读必须带让球线符号(2026-09-15, 坑#38)**: `hhad` 的 h/d/a 是**主队让球后**的结果 —— 主队让球(line<0)时"让胜"=让球方赢够; 主队**受让**(line>0)时"让胜"=受让方(主队)守住。一律按 line<0 套文案会把**客队让球**的场次说反(012 伊普斯+1 vs 阿森纳: 重的一侧是阿森纳赢够45.2%, 旧版印"受让方不败")。调 `handicap_side(q, line)` 必须传线; 详见 `自改进总结_20260915.md`
- **2026-09-15 周一 11 场复盘实测**: 让球盘 **让胜2/走水4/让负5**(走水36% = 基准的1.6倍); 选边8场 **兑现2/走水4/打穿2**; **判"让球方赢够"0/2**; 胜平负 市场方向8/9、模型5/5(n=5不可外推); 坑#29平赔分档当天反向(n=2对n=9, 只记不改)。**教训: "赢不够"≠"赢不了"** —— 010 按"利兹联赢不了"写, 实际 4:1。详见 `00_引擎/backtest/REVIEW_20260915_0914.md`
- ⚠️ **2026-09-16 复盘 + 可信度复核(坑#41)**: 三天 20 场判"受让方不败" → 兑现6/走水6/打穿8; 但**按线型算基准期望是打穿6.3/兑现9.6, 二项检验 p=0.282 不显著**(属波动, 别把它当"这条线不行"的证据)。**真正有 498 场支撑的是"让球方赔率→赢盘率"**: ≤1.30→**52.9%** / 1.30-1.60→**38.5%** / 1.60-2.00→**20.6%** / >2.00→**21.6%**(主让且>1.60 仅 **17.4%**)。**判据 v2: 让球方赔率 ≤1.60 不把"受让方不败"当主线; >1.60 才是主流形态**; 原"近5场进球/失球"判据无历史字段可回测 → 降级为减速带。**同时区分"判断错"与"运气差"**(001/005 基准站我们这边属运气; 003/011 才是判断错)。**"数据打假"仍优先**(004 柔佛 44 球被拆穿→1:1 兑现)。详见 `00_引擎/backtest/REVIEW_20260916_0915.md` / `.uv-cache/verify_rule_0916.py`

## 6. 复盘与研究纪律
- 新赛果 → `matches_YYYYMMDD_latest.tsv`(**只写旧 TSV 没有的场次**, 防双计) → `weekly_update.py` → 看"样本 N 场"确认增量
- 该场有赛前 config → 复盘写**完整版 JSON** 进 `reviews/`; 纯赛果写轻量版
- **赛前与赛果偏差两段都要分析, 不管该场有没有深入模型分析**(全量过筛)
- 证据优先级: **竞彩网 > 外媒**; titan007 数据页最全(球队级: 积分/近10场战绩+盘路/伤停/赛程/评分); 数据页与助手记忆冲突时**以数据页为准**; 外媒标注来源融入叙事
- **竞彩官方 API 全盘口**(2026-09-10 实测): `webapi.sporttery.cn/gateway/uniform/football/getMatchCalculatorV1.qry?channel=c&poolCode=had,hhad,ttg,crs,hafu` 一次取**当日全部场次**的编号/bettingSingle/让球/进球数/比分/半全场 → 脚本 `02_工具/jingcai_fetch.py`(**队名须用官方全称子串**, 如"曼彻斯特联"而非"曼联"; 无参=列场次); titan007 页赔率=其镜像, 交叉核对用
- ⚠️ **竞彩网「伤停一览」残缺不可用**(2026-09-10 两次实证: 拜仁场只列2人, 曼联场仅列1人) → 伤停以 titan007 页 + 2-3家外媒 + 开球前首发官宣为准
- ⚠️ titan007 赔率常**粘成一串**, 且首位可能是**整数盘**(进球数 0球=50) → 反解须允许无小数 token, 并用"返还率须落在 [1.05,1.35]"过滤
- **运行方式(2026-09-12 建档)**: 项目根 `.\run.ps1 <脚本> <参数>` 一键跑(自动用 `.venv` + 设好 `PYTHONIOENCODING`/`UV_CACHE_DIR`); 依赖清单 `requirements.txt`(Python 3.11, 非 3.14 — faiss/sentence-transformers 无 3.14 轮子)
- ⚠️ **本机网络三特征(2026-09-12 实测)**: ①Python 直连(urllib/requests)通, 但 **Chrome/Edge 默认走系统代理 → 访问 inter.it/titan007 报 ERR_CONNECTION_CLOSED**, 无头抓取须加 `--no-proxy-server`; ②**竞彩官方 webapi 用 requests 直连吃 567**, 经浏览器上下文(带 Referer+指纹)可稳定取到 → 统一走 `采集数据/browser.py` 的 `fetch()`/`fetch_api()`; ③playwright 自带 chromium **装不上(下载器 spawn EPERM)**, 也不需要 —— 用 `channel='chrome'`/'msedge' 驱动本机浏览器
- `read_file` 对中文 md 可能误判 binary → 改用 `cat`
